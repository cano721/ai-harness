# /board — Harness Board

자동 harvest·sync·자동 병합은 플러그인 정기 실행이 하고, 보드는 **보여 주고 사람이 답하는 화면**이다. 인자: `$ARGUMENTS` — 없거나 `open`이면 열기, `stop`이면 끄기, `status`면 상태.

경로 표기: 아래 `$ROOT` = 이 SKILL.md가 있는 디렉터리의 두 단계 상위(플러그인 루트).

## 열기 (`open`, 기본)

```bash
$ROOT/scripts/board/board.sh open
```

- 이미 떠 있으면(`~/.ai-harness/board/server.json`의 pid가 살아 있는 보드 서버) 그 주소를 다시 연다(`reused: true`). 없으면 백그라운드로 띄운다. 그다음 macOS 창 앱(`launcher status`의 `kind=window`)이 있으면 그 창으로, 없으면 브라우저로 연다.
- 출력 한 줄 JSON의 `url`(토큰 포함)을 사용자에게 그대로 보여 준다. 브라우저가 열리지 않는 환경이면 그 주소를 직접 열라고 안내한다. 이 주소의 토큰은 보드를 조작할 수 있는 열쇠이므로 PR·이슈·공유 문서에는 적지 않는다.
- 실패하면(종료 코드 1) stderr 이유를 그대로 전한다. `BOARD_PORT`를 정하지 않으면 8765가 막혀 있어도 다음 빈 포트(최대 8774)로 띄운다 — 실제 주소는 출력 JSON의 `url`을 쓴다. 10개가 모두 막혔거나 정한 `BOARD_PORT`가 막혔을 때만 멈춘다 — 그때 다른 포트로 띄울지 사용자에게 묻고, 원하면 `BOARD_PORT=<포트> $ROOT/scripts/board/board.sh open`. 이전 버전 서버가 주소 없이 떠 있다는 메시지면 `stop` 뒤 다시 열지 묻는다.
- 창 앱도 브라우저도 열지 않고 주소만 원하면 `--no-browser`.

## 끄기 (`stop`) · 상태 (`status`)

```bash
$ROOT/scripts/board/board.sh stop
$ROOT/scripts/board/board.sh status
```

`stop`은 보드 서버만 끈다(`server.json`의 pid가 보드 서버일 때만 신호를 보낸다). 작업 세션·worktree·상주 세션 호스트는 건드리지 않는다. `status`는 `running`·`url`을 보여 준다.

서버는 보는 사람(열린 보드 화면)이 `BOARD_IDLE_EXIT`분(기본 30, `0`이면 끄지 않음) 동안 없으면 스스로 꺼진다. 붙잡은 권한 요청이나 열린 이벤트 연결이 있으면 끄지 않는다. 상주 세션은 보드가 아니라 호스트가 쥐므로 보드가 꺼져도 그대로 돈다.

**상주 세션 호스트 — 세션을 쥔 동안만 사는 프로세스**: 보드가 띄운 상주 세션은 보드 서버와 따로 사는 호스트(`scripts/board/resident_host.py`)가 쥔다. 보드는 필요할 때(새 세션·보내기·이어 쥘 세션이 있을 때) 호스트를 분리해서 띄우고 `~/.ai-harness/board/host/`(0700) 아래 유닉스 소켓(0600)으로 붙는다 — 요청마다 `host.json`(0600)의 토큰이 필요하고 같은 사용자만 받는다. 상시 데몬이 아니다: 살아 있는 상주 세션도 보드 연결도 없으면 `BOARD_HOST_IDLE`초(기본 300) 뒤 스스로 끝나고, launchd 같은 로그인 항목은 만들지 않는다. 그래서 `stop`·플러그인 업데이트 뒤 재기동에도 세션 프로세스와 붙잡은 권한·질문이 남고, 다시 연 보드에 바로 보인다(사람 대신 답하지 않는다). 재부팅 등으로 호스트가 꺼졌으면 다음에 보드를 열 때 새 호스트가 사람이 끝내지 않은 48시간 안 세션을 같은 id로 `--resume`해 입력 대기로 둔다(8개까지, 입력 전에는 모델을 부르지 않는다, 이전 프로세스가 아직 살아 있으면 건너뜀). 그때 끊긴 작업·요청이 있었던 세션은 카드에 "끊긴 요청이 있었음 — 다시 보내 이어가기"를 보인다. 사람이 "세션 끝내기"로 끝낸 세션만 끝난 것으로 기록해 다시 띄우지 않는다.

**호스트 끄기·버전**: `$ROOT/scripts/board/board.sh host-stop`은 호스트를 끈다 — 쥔 세션의 stdin을 닫아 끝내고(대화 기록 유지, 사람이 끝낸 것으로 기록하지 않음), 다음 호스트가 뜰 때(보드가 열려 있으면 곧바로) 같은 id로 `--resume`해 이어 쥔다. 호스트는 `host.json`에 대화 형식(`proto`)·플러그인 버전·스크립트 경로를 남긴다. 플러그인이 업데이트돼 보드와 경로가 다르면, 쥔 세션이 없을 때 보드가 옛 호스트를 끄고 새로 띄운다. 세션이 있으면 형식이 같을 때만 그대로 쓰고 작업 현황 위에 "이전 버전 호스트가 상주 세션을 쥐고 있음 — 세션을 끝내면 새 버전으로 바뀜"을 보이며, 세션이 다 끝나면 바꾼다. 형식이 다르면 그 호스트는 부르지 않고 안내만 보인다 — 사용자가 바로 바꾸고 싶어 하면 `host-stop`을 안내한다.

## 런처 앱 (macOS, 선택)

`/ai-harness:board` 없이 눌러서 여는 앱 `~/Applications/Harness Board.app`은 `/ai-harness:setup`의 자동화 옵션(8-3)으로 사용자가 고를 때만 만든다. 이 스킬은 몰래 만들지 않는다. 상태 확인·지우기는 `$ROOT/scripts/board/board.sh launcher status|remove`. 앱은 고정 경로 `~/.ai-harness/board/bin/open-board`를 부르고, 그 스크립트가 열 때마다 가장 새 플러그인 설치본의 `board.sh open`을 부른다 — 플러그인을 업데이트해도 다시 설치할 필요가 없다. 열지 못하면 이유를 대화상자로 보이고 `~/.ai-harness/board/launcher.log`에 남긴다(보드 주소·토큰은 남기지 않는다). 앱은 보드를 자기 창(WKWebView) 하나에 띄우고 보드가 떠 있는 동안 Dock에 남는다 — Dock 아이콘을 다시 누르면 새 탭 없이 그 창을 앞으로 가져오고, 창을 닫거나 앱을 종료하면 보드 서버도 끄며, 보드가 자동 종료나 `board.sh stop`으로 꺼지면 몇 초 안에 따라 끝난다. 설치 때 `swiftc`가 없으면 누를 때마다 브라우저로 여는 AppleScript 앱이 대신 설치된다(`launcher status`의 `kind`: `window`/`applet`). `kind=window`가 설치돼 있으면 `/ai-harness:board`·`board.sh open`도 그 창으로 연다(떠 있으면 앞으로).

## 보드가 하는 일과 하지 않는 일

화면은 사이드바의 **작업 현황**(한 목록)·내 일정·레퍼런스·하네스 효과·하네스 설정·하네스 안내 여섯이고, `docs/design-system.md`의 공용 부품(`ds-`)으로 그린다. 작업 현황은 탭 `전체 | 작업 | 하네스 동작 | 자동 수정`(탭마다 지금 할 일 수 — 사이드바·칸 제목과 같은 수)으로 출처를 거르고, 맨 위 **지금 할 일**(권한 요청·답 대기·자동 수정 사람 판단·PR 검토, 카드마다 주 동작 하나) 아래 진행 중 → 대기·막힘(같은 원인 셋 이상은 한 줄로 묶음) → 읽지 않은 결과(접힘) → 끝난 일(접힘)을 놓는다. 전체 탭에서는 카드마다 출처 칩을 단다. 모든 카드는 키보드로 열리고, 열면 서랍이 목록 옆에 서고 목록은 한 줄로 접힌다(좁은 폭에서는 배경을 가리고 뜬다). 카드 한 장에는 상태 배지가 하나다.

- **작업**: `claude agents --json --all`과 세션 대화 기록으로 상태를 보여 준다. 쉬는 세션의 마지막 답이 질문으로 끝나면(마지막 문장만 보고, 사람이 그 뒤에 답하지 않았을 때만 — `scripts/board/asks.py`) '답 대기'로 지금 할 일에 올리고 그 질문 문장을 카드에 보인다. git 저장소가 아닌 작업 폴더는 사이드바에서 저장소로 세지 않는다. 대화 보기(위로 올리면 이전 대화), 입력 보내기(보드가 쥔 상주 세션은 stdin으로 바로, 입력을 기다리는(idle) 백그라운드 세션은 `claude attach`를 PTY로 붙여 원래 세션에 넣고 떼며 대화 기록에 들어갔는지 확인 — `--resume`은 복제본을 띄우므로 쓰지 않는다, 멈춘 백그라운드 세션은 같은 ID로 `--resume`, 작업 중이거나 질문·권한 창(또는 사용량 한도)에서 기다리는 백그라운드 세션은 보내지 않고 attach 명령을 안내, Orca 터미널의 대화형 세션은 그 터미널에 입력), 질문(AskUserQuestion) 답 버튼, 권한 요청 허용/거부, 읽음 처리, 끝난 세션 정리. 설정 폴더 모으기: 기본 폴더(`~/.claude`) 외에 서버 환경의 `CLAUDE_CONFIG_DIR`, Orca 프로필 폴더(`BOARD_CLAUDE_PROFILE_GLOBS`, 기본 `~/Library/Application Support/orca/claude-profiles/*/home`)를 자동으로 찾아 폴더마다 `claude agents`를 불러 합치고(폴더들을 동시에 부른다), 그 밖의 폴더는 `BOARD_CLAUDE_CONFIG_DIRS`(`:` 구분)로 더한다. 입력·재개·정리는 그 세션이 속한 설정 폴더로 보낸다. 보드가 열려 있는 동안 서버가 상태를 뒤에서 다시 모아 두고(기본 2초 `BOARD_REFRESH_SECONDS`, 직전 수집 시간의 두 배보다는 짧게 하지 않는다, 1분 넘게 아무도 안 보면 쉰다) 화면은 1초마다 그 캐시만 읽는다. 하네스 기록·세션 상태 파일(`sessions/`·`jobs/`)의 크기·수정 시각 지문이 그대로면 전체 수집을 건너뛰고(일하는 세션의 대화 기록·러너 진행 로그만 바뀌었으면 `BOARD_TRANSCRIPT_REFRESH_SECONDS` 기본 10초마다, 아무것도 안 바뀌어도 `BOARD_FULL_REFRESH_SECONDS` 기본 30초마다는 모은다 — 시각에 따른 판정은 최대 1분 늦을 수 있다), 다시 모을 때도 그대로인 하네스 기록·설정 폴더별 `claude agents` 목록은 그 동안 지난 결과를 쓴다(`~/.ai-harness/board/status-cache/`·`agents-cache/`, 0600). 마지막 목록은 `~/.ai-harness/board/snapshot.json`(0600)에 남겨 보드를 다시 띄우면 그것부터 보이고("N분 전 저장한 목록입니다" 표시) 새 수집이 끝나면 바뀐다.
- **attach로 보내기의 한계**: 권한 창에서 Enter는 기본 선택지(허용)를 고른다. 보드는 붙기 전·붙여넣기 전·Enter 전에 `claude agents`로 입력 대기인지 보고, 화면에 질문·권한 창 표지(`Do you want to`·`❯ 1.`·`Esc to cancel` 등, Claude Code 2.1.326 실측)가 보이면 멈추며, 붙여넣은 글이 입력창에 보일 때만 Enter를 보낸다. 그래도 마지막 확인과 Enter 사이(1초 안팎)에 세션이 스스로 창을 띄우면 막지 못한다 — 입력을 기다리는 세션은 사람 입력 없이 도구를 부르지 않아(백그라운드 작업 알림으로 깨는 경우 제외) 드물다. Claude Code가 창 문구를 바꾸면 표지를 다시 맞춘다. 멈춘 경우 붙여넣은 글은 입력창에 남을 수 있고(지우는 키는 창에서 거절·중단으로 읽혀 보내지 않는다) 응답 메시지가 그렇게 알린다. 다른 터미널에서 같은 세션 입력창에 쓰던 초안이 있으면 보낸 글이 그 뒤에 붙는다.
- **보드가 쥔 새 세션(상주 세션)**: '새 세션'은 `claude -p --input-format stream-json --output-format stream-json --verbose --permission-prompt-tool stdio`로 띄워 상주 세션 호스트가 stdin·stdout을 쥔다(`scripts/board/resident.py`, 위 "상주 세션 호스트"). 이어서 보내기는 같은 프로세스의 stdin으로(`--resume` 없음, 세션 id 유지), 권한 요청·AskUserQuestion은 세션이 보드에 직접 묻는 요청(`control_request`)으로 받아 화면에서 허용/거부·보기 선택으로 답한다(`POST /permission`, `POST /answer`). 화면은 `GET /events`(SSE)로 바뀐 항목만 받고, 끊긴 동안만 1초 폴링(서버 캐시 읽기)으로 돌아간다. SSE 연결도 보는 사람으로 쳐서 백그라운드 갱신이 쉬지 않고, 갱신이 캐시를 새로 쓸 때마다 바뀐 항목을 민다. 숨은 탭은 연결을 닫고 `bg=1` 폴링으로 돌아가며, `/events?bg=1`은 갱신을 살리지 않는다. 카드의 "세션 끝내기"는 세션을 닫지만 대화 기록은 남고, 기록(`~/.ai-harness/board/residents.json`, 0600)으로 다음에 보내면 `--resume <id>`로 같은 id를 다시 쥔다. 보드를 꺼도 세션은 닫히지 않는다. 답을 기다리던 요청은 닫힐 때 실패(거절)로 끝난다.
- **내 일정(#492)**: 작업 현황과 별개로 사람의 일정·답할 것·할 일을 모은다. 편집기 옆 좁은 폭에 띄워 두는 1단 화면이다(#567) — 머리에 로컬 날짜·시각과 **[⚙ 연결 N]**(누르면 **연결한 곳** 줄 목록이 열린다: 소스마다 상태 배지 하나·마지막 수집 시각·버튼 하나: 연결 / 끊기 / 설정하기 / 계정 추가, 계정을 여럿 잇는 소스는 그 아래 계정 줄마다 끊기와 필요하면 다시 연결. 연결된 소스가 없으면 기본으로 펼침), 끊김·오류가 있는 소스만 한 줄 알림, **지금·다음** 카드 하나(오늘의 시각 있는 일정 중 팀 공유가 아닌 것: `지금 HH:MM–HH:MM 제목`·`다음 HH:MM 제목 · N분 뒤`, 남은 게 없으면 `오늘 남은 일정 없음 / 내일 첫 일정`)와 그 아래 회색 접힘 줄(종일·팀 부재·지난 일정), 접힌 아침 요약, **답할 것**(있을 때만, 강조 제목·출처), **새로 맡겨진 요청**(받은 지 24시간 이내), **기한 있음**(기한순), 할 일 적기, 그 아래 접힌 버튼 **쌓인 요청 N**(오래된 순·경과일, 요청자가 있으면 [전체|요청자별] 선택)·**내일 … · 이번 주 N**(날짜별 한 줄 → 그날 일정)·**완료함 N**(최근 7일, [다시 열기] 또는 원본에서 다시 열기 안내). 0건인 절·버튼은 그리지 않는다. 소스는 어댑터 선언 `agenda.json`이다: 플러그인 기본 `scripts/board/agenda/*/`(구글 캘린더) → `~/.claude/skills/*/`(`HM_CLAUDE_SKILLS_DIR`) → `~/.agents/skills/*/`(`HM_CODEX_SKILLS_DIR`) 순으로 찾고 같은 id는 먼저 찾은 쪽이 쓴다. 필드: `id`(소문자·숫자·`-`)·`name`·`fetch`(argv, 상대 경로는 그 폴더 기준), 선택 `interval_minutes`(기본 15)·`connect`·`disconnect`·`done`·`reopen`(#567)·`accounts`(argv)·`requires`(있어야 할 파일, `~`·`$HM_DATA_DIR` 펼침)·`setup_hint`·`setup_prompt`(설정 세션 안내, 1000자까지). `fetch`는 `--since ISO --until ISO`(오늘 0시부터 7일)를 덧붙여 부르고 stdout JSONL 한 줄이 항목 하나다 — `{id, kind: event|reply|todo, title, start?, end?, due?, created?, from?, shared?, url?, detail?, done?}`(`due`는 답할 것·할 일의 기한: 날짜 또는 ISO 날짜·시각, #539. `created`는 받은 시각 ISO 8601 — 읽을 수 없으면 버림, `from`은 요청자 60자, `shared`는 팀·공유 캘린더 일정, #567. 구글 어댑터는 내 것이 아닌 캘린더 일정에 `shared`를 단다. `url`(`link`도 받음)은 `http(s)` 또는 허용한 앱 딥링크 스킴 — 지금은 `msteams:` 하나, #592 — 만 남고 그 밖의 스킴(`javascript:`·`file:`·`data:` 등)은 url만 버린다. 앱 링크는 보드가 새 탭 없이 '앱에서 열기'로 넘겨 OS가 그 앱을 연다. 앱이 설치돼 있지 않은 사용자를 위해 웹 링크를 줄지는 어댑터가 정한다), 잘못된 줄은 건너뛰고 세며 소스당 500개까지, 60초를 넘기거나 0이 아닌 종료는 실패다. `requires` 파일이 없으면 [설정하기] — `setup_prompt`를 선언한 소스는 서버가 그 안내를 고정 머리말·비밀 규칙 꼬리말로 감싸 하네스 설정 > 스킬과 같은 장치(`POST /settings/skills/session {kind: "agenda", name: <소스 id>, action: "setup"}`, 기록은 `skill-sessions.json`의 `agenda:<id>`)로 홈 폴더에 설정 세션을 띄워 작업 현황에 보이고, 진행 중이면 버튼을 막고 진행 줄과 세션 링크를 보이며, 세션이 끝나면 소스 상태를 다시 읽는다. `setup_prompt`가 없는 소스는 안내 한 줄을 펼친다(#525). 연결 안 됐으면 [연결](`connect`가 있으면 뒤에서 최대 5분 — 브라우저 동의, 끝나면 연결됨), 연결됐으면 [끊기](`disconnect`를 부르고 캐시를 지움). `accounts`를 선언한 소스(#519)는 계정을 여럿 잇는다 — `accounts`가 JSONL `{id, name, error?}`로 계정 목록을 내고, 연결된 뒤에도 [계정 추가]가 `connect`를 다시 부르며, 계정 줄의 [끊기]가 `disconnect <계정 id>`로 그 계정만 끊는다(마지막 계정이면 소스도 끊김). 계정 목록은 연결·끊기·수집 뒤에 다시 읽고, `error`가 있는 계정은 '다시 연결 필요' 배지와 [다시 연결](= `connect`)을 단다. 연결된 소스만 `interval_minutes`마다(화면이 읽을 때와 서버의 1분 타이머) 소스마다 자기 스레드로 수집해 `~/.ai-harness/board/agenda/cache/<id>.json`에 둔다. 한 소스가 실패하면 그 소스의 이전 항목을 그대로 두고 화면 위 알림 줄 하나와 '가져오기 실패' 배지로 알린다. 완료는 답해야 할 것·할 일만 — `done`을 선언한 소스는 `done <항목 id>`를 불러 원본에도 반영하고, 없으면 보드(`done.json`)에만 적어 숨긴다. `reopen`을 선언한 소스는 `reopen <항목 id>`로 원본의 완료를 되돌린다(#567). 완료함(`completed.json`)은 최근 7일 완료(직접 적은 할 일·보드에만 숨긴 항목·어댑터 done)의 출처·id·제목·url·시각만 남기고(본문 없음) 7일 지난 줄은 읽고 쓸 때 지운다. 일정은 소스·계정·시간대 오프셋과 무관하게 실제 시각순(로컬 날짜, 종일 먼저)이다. 연결 상태·캐시·완료 기록·할 일·구글 토큰은 `~/.ai-harness/board/agenda/` 아래 600 권한이고, harvest·지표 수집 대상이 아니다. 구글 캘린더는 플러그인에 든 공용 데스크톱 OAuth 클라이언트(`scripts/board/agenda/google/client.json`)로 바로 연결되고, 사용자가 직접 만든 클라이언트(`~/.ai-harness/google-oauth-client.json`)가 있으면 그것을 쓴다. 계정마다 토큰을 `google-accounts/<계정>.json`에 두고 일정을 합친다(같은 캘린더는 한 번) — `/ai-harness:setup` 8-4, `docs/privacy.md`. 화면(#539·#567): '아침 요약'(`brief.json`, 오늘 받은 것만)은 접힌 한 줄, 할 일 줄은 한 줄(완료 원 | 제목 | 요청자·경과일 또는 기한 배지 | 원본 열기는 hover·포커스 때만, 출처 칩은 출처가 섞일 때만)이다. 할 일·완료함 줄의 제목은 펼쳐 보는 버튼이다 — 누르면(Enter·Space) 잘린 제목 전체가 줄바꿈되고 `detail`이 있으면 그 줄 아래에 보이며, 다시 누르면 접힌다(#590). 할 일(직접 적은 것 + 어댑터 todo)은 기한 있음 > 새로 맡겨진 요청(`created`, 없으면 이 브라우저가 처음 본 시각이 24시간 이내) > 쌓인 요청 순으로 하나에만 든다. 완료 토스트의 [되돌리기]는 직접 적은 할 일·보드에만 숨긴 항목·`reopen`을 선언한 소스(`done` 응답 `undo`), 아니면 원본에서 다시 열라고 안내한다. 이 브라우저가 처음 보는 항목은 '새로'(localStorage `hb-ag-seen` = `{key: 처음 본 시각}`, 예전 배열 값과 처음 읽을 때의 항목은 오래전 본 것으로 둠), 사이드바 '내 일정'에는 새로 온 수, 없으면 기한 지난 수. API: `GET /agenda`, `POST /agenda/connect {source}`, `POST /agenda/disconnect {source, account?}`, `POST /agenda/done {source, id}`, `POST /agenda/reopen {source, id}`, `POST /agenda/todo {text, due?}`(모두 토큰·Origin·Host 검사, 응답·기록에 토큰·client secret 없음).

"다시 계산"은 오늘 결과가 있어도 새로 돌린다. 실패(설치일 모름 exit 3 등)는 이유와 함께 보이고 그날은 자동으로 다시 돌리지 않는다. 맨 위에 전체 한 줄과 저장소별 한 줄 상태(효과 확인·엇갈림·재발/악화·관찰 중·데이터 부족·최근 세션 없음, 신호가 없으면 왜 모르는지)를 두고, 최근 세션이 없거나 계산하지 못한 저장소는 아래에 접는다. 저장소마다 세션당 교정·사실 부족의 설치 후 주별 추세(줄고 있음·비슷함·늘고 있음·데이터 부족)가 주 지표이고, 설치 전후 비교는 표본이 충분할 때만 숫자로, 아니면 "비교 불가 — 설치 전 기록 없음"처럼 이유를 보인다. 상태·추세·비교 가능성은 `impact.sh view`(`scripts/impact-assess.jq`)가 정한 값이고 `/harness-impact` 리포트와 같다 — 보드는 규칙을 갖지 않는다. 개선은 펼쳐 보는 줄(최신순, 규칙 제거는 따로)이고 판정 배지는 리포트와 같은 낱말(사라짐·줄어듦·재발·판단 보류·기준 없음·판정 안 함)이다. 제목은 요약의 첫 문장, 원문·근거는 줄을 펼친 곳에 둔다. 카드의 판정은 `/harness-impact`가 그 저장소에서 마지막으로 맞춘 매칭을 그날까지의 세션에 다시 쓴 값이다(`impact.sh view`) — 보드는 같은 유형인지 맞추지도, 판정 규칙을 갖지도 않는다. 매칭이 없으면 반영 뒤 관찰 세션이 5개 미만은 "판단 보류", 아니면 "판정 안 함"이고, 판정을 채우려면 그 저장소에서 `/ai-harness:harness-impact`를 돌리라고 안내한다 — LLM 토큰이 드는 선택 동작이라 보드가 자동으로 돌리지 않는다(설치 전 세션 정리도 같다). 보드 계산은 bash·jq 집계뿐이다. "전체 리포트 열기"는 `impact.sh render`로 오프라인 리포트를 `~/.ai-harness/reports/`에 만들어 연다. 읽기 전용 — 개선을 되돌리거나 하네스를 고치지 않는다.
- **자동 수정(목록 카드)**: `autofix-auto.sh status`의 에러 시그니처마다 카드 한 장 — 상태 배지 하나(사람 판단·PR 검토·수정 중·배포 대기·재발 관찰 중·재발·실행 실패·해결·건너뜀), 로그 원문 대신 사람 말로 다듬은 제목(시각·로그 수준·추적 ID·해시·로거 위치를 걷어 냄, 원문은 서랍에), 감지 건수. 카드를 열면 서랍에 단계·원인 분석 요약(실행 로그의 결과 텍스트, 비밀값·홈 경로 가림)·원문 제목·모니터링 링크·로그·PR이 보인다. "세션으로 열기"로 띄운 세션은 그 에러 카드에 합쳐져("이어 보는 세션") 따로 카드가 생기지 않는다. 상태 열: 넘김(`left_for_user`)·포기·실패·PR 검토 대기 → 사람 필요, 수정 중·검증 중 → 진행 중, 재발 → 대기, 해결·PR 닫힘·그 밖의 건너뜀 → 완료. PR이 호스트에서 병합되면 진행 중, 닫히면 완료로 옮긴다(`prstate`). 사람 필요 카드의 "세션으로 열기"는 그 저장소에서 원인 요약을 넘긴 세션을 띄운다(사람이 누를 때만). 상태 파일을 잃고 실행 기록에만 남은 실행도 카드로 보인다.
- **자동 수정(탭 위 한 줄 상황·후보)**: 무인 실행 켜짐/꺼짐 · 오늘 실행 수/상한 · 누적 비용 · 최근 실행 결과와 하네스 설정으로 가는 버튼, 지금 할 일 아래 **후보**(저장소마다 "후보 조회" — `autofix-auto.sh candidates`, 버튼으로만). 후보 줄을 펼치면 왜 후보인지·서비스·처음/마지막 본 때·관련 세션·모니터링 링크·원문 제목이 보이고, "원문·스택 불러오기"(`monitor-fetch.sh detail`, 후보 조회 때 남긴 조회 정보로 다시 찾음, 비밀값 가림)는 누를 때만 돌고 결과를 남긴다. 이미 상태 기록이 있는 에러는 후보에 다시 싣지 않고 카드가 말한다. 맨 아래에는 카드가 보여 주지 않는 최근 기록(건너뛴 이유·상태 기록·검증 오류)만 접어 둔다.
- **자동 수정(하네스 설정의 "자동 수정" 탭 — 저장소별 연결 → 개인 설정 순)**: 연결은 문제 있는 저장소만 행으로 보이고(나머지는 접음), 대상 저장소는 켜고 끄는 칩이다. `/ai-harness:autofix`의 저장소별 준비 상태(`scripts/monitor-fetch.sh describe` — 요청 없이 monitor 설정 출처(개인 로컬 파일·저장소 manifest·없음)·provider·query 요약·자격증명 있음/없음만, 값은 싣지 않음)와 무인 실행 대상 여부를 보여 준다(`autofix-auto.sh configure`로 대상 여부를 읽는다). 접근 확인(`monitor-fetch.sh check`, 종료 코드 4 = 자격증명·설정 오류, 5 = 설정 없음)은 모니터링 도구 API를 부르므로 버튼으로만 돌리고 결과를 `~/.ai-harness/board/autofix/`에 남긴다 — 화면을 열어도 다시 부르지 않는다. 설정이 없거나 틀린 저장소는 "설정하기"로 그 저장소에서 `/ai-harness:autofix setup` 세션을 띄운다(보드는 monitor 파일을 쓰지 않는다). 하네스 설정의 "자동 수정" 탭(무인 실행·대상 저장소·sweep 주기·하루 상한·에러당 PR 상한·실행당 예산 — 주기·하루 상한·예산은 직접 입력도, 하루 상한·예산은 "제한 없음"도 받고 그때 비용 경고를 보임)은 `autofix-auto.sh configure`로만 쓰고, 주기를 바꾸면 `schedule.sh install-autofix`(sweep 전용 에이전트만 등록·해제, backfill은 그대로, 등록 즉시 실행 없음)와 `status` 결과를 보여 준다. 화면 보기·상태·검증은 LLM이 들지 않고, 수정 실행은 에러마다 LLM 세션이라 비용이 든다 — 보드는 수정 실행(sweep)을 시작하거나 PR을 병합하지 않는다.
- **하네스 안내**: 하네스가 무엇인지, 처음 쓰는 사람의 시작 3단계(셋업 → 프로젝트 하네스 만들기 → 기능 개발, 각 단계는 그 카드로 이동), 순환 흐름(설치 → 작업 → 기록 → 자동 개선 → 동기화 → 효과 확인 — 단계마다 관련 카드 링크와 "자동"·"켜면 자동"·"직접 실행" 칩, 자동 개선·동기화는 하네스 설정의 하네스 동작 탭에서 켤 때만 저절로 돈다 — 자동 개선은 세션이 끝난 뒤나 정기 실행 때, 동기화는 정기 실행 때), 그리고 기능 목록을 묶음별 카드로 보인다. 목록 위에는 묶음 이름과 개수로 가는 목차가 있고(좁은 폭에서는 줄바꿈), 사람이 부르지 않는 스택 규칙과 에이전트는 "에이전트가 알아서 쓰는 것" 한 묶음으로 기본 접혀 있다(`guide.json`의 `"fold": true`). 보드를 처음 연 사람(브라우저에 저장한 화면·탭이 하나도 없음)은 이 화면으로 시작하고, 이미 쓰던 사람은 마지막 화면 그대로다. 보드 주소에 `&view=guide`(`?view=guide`)를 붙이면 바로 열린다. 목록은 `GET /guide`가 `scripts/board/guide.py`로 저장소의 `skills/*`·`templates/*`·`agents/*`·`catalog/catalog.json`을 읽고 `scripts/board/guide.json`의 한국어 이름·한 줄 요약·말로 부르는 예·관련 보드 화면을 붙여 낸다. 카드마다 부르는 명령(플러그인 스킬 `/ai-harness:<이름>`, 워크플로·카탈로그 `/<이름>`)과 "명령 복사", 관련 화면이 있으면 그 화면으로 가는 링크가 있다. 명령이 있는 카드에는 주 동작 "실행"이 있다(#442, 채운 주 버튼은 "처음이면 이것부터" 세 카드만이고 나머지는 재생 아이콘이 붙은 기본 버튼) — 누르면 "<카드 이름> 실행" 양식이 그 명령(뒤에 덧붙일 수 있음)·카드 이름으로 채워져 열리고, 띄우면 기존 `POST /new`로 상주 세션을 시작해 "작업 현황 열기" 링크가 든 성공 토스트(닫을 때까지 남음)를 보이고 안내 화면에 머문다. 범위는 `guide.json` 항목의 `"run"`이 정한다: `global`(셋업·플러그인 업데이트·사용량 리포트·카탈로그 — 저장소 칸 없이 홈에서), `repo`(저장소 코드를 읽거나 바꿈), `harness`(워크플로·자동 개선·하네스 효과 — 하네스를 깐 저장소만), `optional`(다이어그램·레퍼런스 모으기·랜딩 페이지·듣는 사람에 맞춰 설명 — 목록 맨 위에 "저장소 없이(홈에서)"). 저장소는 검색되는 목록에서 고른다(위아래·Enter·Esc, 줄마다 이름·줄인 경로, 하네스를 깐 저장소는 "하네스" 칩, 최근 사용 순, 맨 아래 "다른 경로 직접 입력"). 처음 고른 값은 아무 저장소도 아니다 — optional은 "저장소 없이(홈에서)", repo·harness는 후보가 하나일 때만 그것이고 아니면 고르기 전에 띄우면 칸 아래 오류로 저장소를 고르라고 한다. 새 세션 버튼은 지난번 고른 곳을 남긴다. 프로젝트 하네스 만들기는 하네스를 아직 깔지 않은 저장소를 먼저 보인다(`guide.json`의 `"prefer": "unharnessed"`). 후보는 `GET /launch`(안내는 `/guide`에 함께)가 Orca 저장소 목록(`orca repo list --json`), Claude Code 사용 기록(`~/.claude.json`의 `projects` 키만, `HARNESS_CLAUDE_JSON`으로 위치 지정), 보드가 아는 저장소에서 모아 없는 폴더·git 최상위가 아닌 곳·worktree·임시 폴더(`BOARD_TEMP_ROOTS`)·홈을 거른다(모은 결과는 `BOARD_LAUNCH_TTL`초, 기본 30초 동안 다시 쓴다). 최근 사용 순은 그 저장소 경로로 연 Claude Code 대화 기록 폴더의 수정 시각이라, worktree에서만 작업한 저장소는 이름순 뒤로 간다. 작업 현황의 "새 세션"도 같은 목록을 쓴다. 하네스 보드 자신·접힌 묶음·명령 없는 카드에는 실행이 없다. 실행할 수 없으면 버튼이 흐려지고 이유와 풀 곳이 옆에 적힌다: 하네스를 깐 저장소가 없음(→ 프로젝트 하네스 만들기 카드), 기본 스킬 카탈로그 항목을 아직 설치하지 않음(`~/.claude/skills/<이름>/SKILL.md`, `HM_CLAUDE_SKILLS_DIR` 존중 → 처음 셋업 카드). `guide.json`에 없는 기능은 "기타" 묶음에 원래 설명의 첫 문장으로 남고, 저장소와 어긋나면 `tests/board.sh`가 실패한다 — 기능을 더하거나 없애면 `guide.json`도 같이 고친다. 기능 목록은 정적이지만 실행 가능 여부가 바뀌므로 안내 화면을 다시 그릴 때 1분이 지났으면 다시 받는다. 쓰기는 실행(기존 `/new`)뿐이다.
- **바뀐 것과 릴리스 이력(#439, #457)**: 플러그인 버전이 사용자가 마지막으로 확인한 버전보다 높으면 안내 화면 맨 위에 "vA → vB에서 바뀐 것" 패널이 선다. 확인한 버전은 `$HARNESS_METRICS_DIR/board/version-seen.json`(`{seen, prev}`)에 있고 세션 시작 안내와 같은 값이다. `GET /guide/changes`가 `scripts/board/changes.py`로 플러그인의 `CHANGELOG.md`에서 확인한 버전 초과 ~ 현재 버전 이하의 절을 합쳐(건너뛴 버전 포함, `## Unreleased` 제외, 버전은 숫자로 비교) 업데이트 후 해야 할 일(사람 필요) → 새 기능 → 동작 변경 → 버그 수정·기타(한 줄로 접힘) 순으로 낸다. 바닥의 주 버튼 "확인했습니다"는 `POST /guide/changes/seen {to}`(Origin·토큰 검사)로 화면이 보여 준 버전까지만 기록하고 패널을 접는다. 그 아래에는 확인 여부와 무관하게 "릴리스 이력"이 늘 있다 — 버전마다 한 줄(날짜, 해야 할 일·새 기능·동작 변경·버그 수정 수, 확인한 버전 뒤의 릴리스는 "새 버전" 배지)이고 펼치면 그 버전의 묶음이 나온다. 최근 5개만 보이고 나머지는 "이전 릴리스 N개 더 보기"에 접힌다. 항목은 제목 한 줄이고, 펼치면 항목의 `요약:` 줄(사용자용 쉬운 설명) → 화면 캡처(`![설명](assets/release-notes/<파일>)`, "화면 예시" 캡션) → "자세히"(원문) 순이다. 요약·캡처가 없는 옛 항목은 원문이 바로 나오고, 굵은 제목 없이 쓴 항목은 요약이 제목 자리에 선다. 캡처는 `GET /release-notes/<파일>`(토큰 검사)이 플러그인 `assets/release-notes/` 바로 아래의 png·jpg·webp·gif만 내준다(경로 이탈·심볼릭 링크·SVG·그 밖의 파일은 404). 기능 카드의 "새 기능" 배지는 최근 릴리스(최신 릴리스 날짜에서 7일 안, 그보다 적으면 최근 3개 — `recent_from`) 이후 생긴 기능(`guide.json`의 `"since"`)과 확인 안 한 버전에 생긴 기능에 붙고, 같은 최근 릴리스의 새 기능·동작 변경·버그 수정 항목 제목이나 요약이 카드 명령(`/<이름>`·`/ai-harness:<이름>`)을 말하면 "변경됨 vX" 칩이 붙는다. 기능 묶음 목차에도 묶음별 새 기능 수가 보인다. 확인 전에는 사이드바 "하네스 안내"에 해야 할 일 수(사람 필요) 또는 해야 할 일이 없으면 "새 소식" 배지가 붙는다. 확인 상태가 없으면(첫 설치, 이 기능 이전부터 쓰던 사람) 현재 버전으로 조용히 기록해 패널을 쏟아내지 않는다(릴리스 이력은 그대로 보인다). 안내 화면은 보여 줄 데이터가 같으면 작업 상태가 바뀌어도 다시 그리지 않는다. 서버는 `server.json`에 자기 플러그인 폴더(`root`)를 남기고, `board.sh open`은 다른 폴더(업데이트 전 버전)에서 뜬 서버를 끄고 이 버전으로 다시 띄운다(상주 세션은 호스트가 쥐어 이어진다).
- **끝난 일 정리**: 끝난 일 칸 머리의 "끝난 일 정리…"가 범위(하루·일주일 넘은 것, 전체)별로 정리할 항목과 각각 일어날 일(숨김 / 쉬는 세션 닫기 / worktree 삭제 가능·불가와 이유)을 미리 보이고, 확인하면 `POST /cleanup-bulk`로 카드별 정리(`cleanup`)를 한꺼번에 돌린다. 기본은 목록에서 숨기기 + 쉬는 세션 닫기이고, worktree 삭제는 체크박스를 켰을 때만 기존 확인(변경·올리지 않은 커밋·다른 살아 있는 세션 없음)을 통과한 것만 지운다(강제 없음). 작업 중·답 대기·권한 대기 세션은 대상이 아니고 대화 기록은 지우지 않는다. 하네스 동작·자동 수정의 끝난 항목은 숨기기만 하고, 그 항목에 새 일이 생기면 다시 보인다. 같은 정리가 동시에 두 번 돌지 않는다. 숨긴 항목은 "숨긴 항목 N개"(`GET /hidden`, `POST /hidden/restore`)에서 다시 보이게 한다 — 닫은 세션·지운 worktree는 되돌리지 않는다.
- **세션 정리(카드 하나)**: 보드가 닫을 수 있는 세션(백그라운드, Orca 터미널의 대화형 세션)이면 상태와 관계없이 언제나 보인다. 상태는 확인창의 문구와 무게만 정한다 — 쉬는 중·결과 확인은 그대로, 본문 질문 답 대기는 "답하지 않고 닫습니다", 질문 도구·권한 요청 대기는 "그 요청은 거절된 것으로 끝납니다", 작업 중은 "진행 중인 작업이 중간에 끊깁니다"(취소에 기본 포커스, worktree 삭제 불가). 화면은 고른 확인 수준(`confirm`: `idle`·`ask`·`waiting`·`busy`)을 정리 요청에 싣고, 서버는 정리 직전 실제 상태가 그보다 무거우면 거부하며 새 수준을 돌려준다 — 화면은 새 경고로 다시 묻는다. 확인 대화상자는 최근 목록의 항목으로 worktree를 바로 판정한다. 확인하면 카드가 먼저 빠지고, 서버는 정리 직전에 그 세션의 설정 폴더로 `claude agents`를 다시 불러 작업 중·답 대기 여부와 worktree(변경·올리지 않은 커밋·다른 살아 있는 세션)를 다시 확인한 뒤 세션 닫기·worktree 삭제를 뒤에서 한다. 실패하면 숨김을 되돌리고 `status.json`의 `cleanup_failed`로 이유를 알린다. 상태 수집(`work.sh`)은 대화 기록의 제목·요약을 경로·크기·수정 시각 기준으로 `~/.ai-harness/board/work-cache.json`(0600)에 두고 바뀐 것만 다시 읽는다.
- 보드는 다른 세션의 질문·권한에 **사람 없이 답하지 않는다**. 대화 기록(transcript)은 지우지 않는다. 세션 정리와 끝난 일 정리에서 worktree는 변경·원격에 없는 커밋이 없고, 그 폴더를 쓰는 살아 있는 세션(Orca 터미널·에이전트, 보드에서 숨긴 세션 포함)이 없으며 확인에 실패하지 않았을 때만 지운다. Orca 삭제가 실패하면 강제 없이 `git worktree remove`로 넘어간다. 워크플로 러너는 worktree를 지우지 않고 정리 가능 여부만 기록한다.
- 세션이 띄운 세션(부모 대화 기록의 `orca terminal create|agent launch|worktree create` 결과 터미널, `claude --bg` ID)은 부모 아래 묶인다. 대화형 세션은 살아 있는 동안만 `claude agents` 목록에 있으므로, 띄운 기록이 있는 세션이 목록에서 빠지면 `work.sh`가 `links.json`에 고정한 자식(부모가 터미널을 띄운 직후 처음 붙은 세션 — 같은 터미널을 나중에 재사용한 세션은 묶지도 되살리지도 않는다)과 대화 기록으로 끝난 항목을 되살려 묶음과 PR 바로가기를 남긴다(`BOARD_DONE_HOURS` 이내). 사람이 직접 열었다 닫은 세션은 되살리지 않는다.
- Orca는 선택이다. 없으면 세션 묶음과 대화형 터미널 입력만 빠진다.

## 할 일 적기 (`todo`)

보드 '내 일정'의 할 일은 터미널에서도 적고 끝낸다. 보드와 같은 파일(`~/.ai-harness/board/agenda/todos.json`, 잠금·600)을 쓴다.

```bash
$ROOT/scripts/board/board.sh todo add 회의록 정리   # 새 id를 출력
$ROOT/scripts/board/board.sh todo list [--all]      # 열린 할 일 'id<TAB>내용' (--all은 끝낸 것도)
$ROOT/scripts/board/board.sh todo done <id>         # 없는 id면 exit 1
$ROOT/scripts/board/board.sh todo add --due 2026-12-01 보고서 제출   # 기한(날짜 또는 YYYY-MM-DDTHH:MM)
$ROOT/scripts/board/board.sh agenda summary          # 오늘 일정·답할 것·기한순 할 일 JSON(아침 요약 재료)
printf '%s\n' "요약 글" | $ROOT/scripts/board/board.sh brief set --source "아침 요약"   # '내 일정' 맨 위 아침 요약 카드
$ROOT/scripts/board/board.sh brief show
```

## 권한 요청을 보드로 받기 (선택)

보드에서 권한 요청을 허용/거부하려면 PermissionRequest 훅이 필요하다. 이 스킬은 훅을 몰래 연결하지 않는다 — 사용자가 원하면 `/ai-harness:setup`의 자동화 옵션(8-2)으로 연결한다. 훅은 보드가 떠 있고 누군가 보드를 보고 있을 때만 요청을 넘기며, 아니면 아무것도 출력하지 않아 평소처럼 터미널에서 묻는다. headless 세션(`claude -p` — 워크플로 러너·자동 harvest·autofix 같은 자동 실행)의 요청은 보드로 넘기지 않는다 — 답할 사람이 없는 세션을 붙잡으면 그 실행이 멈추므로, Claude Code가 평소처럼 바로 거부하고 세션이 이어 간다.

## 보안

서버는 `127.0.0.1`에만 묶인다. 실행마다 새 URL 토큰을 만들고, 모든 요청의 Host(DNS rebinding 방어), POST의 Origin을 검사한다. 브라우저에서 명령 문자열을 받지 않고 항목별로 허용된 작업만 서버가 인자를 만들어 실행한다. 권한 훅 엔드포인트는 별도 토큰을 쓰며, 그 토큰과 주소는 `~/.ai-harness/board/server.json`(0600, 서버 종료 시 삭제)에만 있다. `server.json`의 `features`(`["references"]`)는 이 서버가 보여 줄 수 있는 화면이다 — `design-refs.sh board --serve`는 이 값이 있는 보드가 떠 있을 때만 따로 서버를 띄우지 않고 대시보드 주소를 안내한다.
