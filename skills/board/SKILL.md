# /board — Harness Board

자동 harvest·sync·자동 병합은 플러그인 정기 실행이 하고, 보드는 **보여 주고 사람이 답하는 화면**이다. 인자: `$ARGUMENTS` — 없거나 `open`이면 열기, `stop`이면 끄기, `status`면 상태.

경로 표기: 아래 `$ROOT` = 이 SKILL.md가 있는 디렉터리의 두 단계 상위(플러그인 루트).

## 열기 (`open`, 기본)

```bash
$ROOT/scripts/board/board.sh open
```

- 이미 떠 있으면(`~/.ai-harness/board/server.json`의 pid가 살아 있는 보드 서버) 그 주소를 다시 연다(`reused: true`). 없으면 백그라운드로 띄우고 브라우저를 연다.
- 출력 한 줄 JSON의 `url`(토큰 포함)을 사용자에게 그대로 보여 준다. 브라우저가 열리지 않는 환경이면 그 주소를 직접 열라고 안내한다. 이 주소의 토큰은 보드를 조작할 수 있는 열쇠이므로 PR·이슈·공유 문서에는 적지 않는다.
- 실패하면(종료 코드 1) stderr 이유를 그대로 전한다. 포트가 다른 프로세스에 잡혀 있으면 띄우지 않고 멈춘다 — 다른 포트로 띄울지 사용자에게 묻고, 원하면 `BOARD_PORT=<포트> $ROOT/scripts/board/board.sh open`. 이전 버전 서버가 주소 없이 떠 있다는 메시지면 `stop` 뒤 다시 열지 묻는다.
- 브라우저를 열지 않고 주소만 원하면 `--no-browser`.

## 끄기 (`stop`) · 상태 (`status`)

```bash
$ROOT/scripts/board/board.sh stop
$ROOT/scripts/board/board.sh status
```

`stop`은 보드 서버만 끈다(`server.json`의 pid가 보드 서버일 때만 신호를 보낸다). 작업 세션·worktree는 건드리지 않는다. `status`는 `running`·`url`을 보여 준다.

## 보드가 하는 일과 하지 않는 일

화면은 사이드바의 **작업 현황**(한 목록)·하네스 효과·하네스 설정 셋이고, `docs/design-system.md`의 공용 부품(`ds-`)으로 그린다. 작업 현황은 탭 `전체 | 작업 | 하네스 동작 | 자동 수정`(탭마다 지금 할 일 수 — 사이드바·칸 제목과 같은 수)으로 출처를 거르고, 맨 위 **지금 할 일**(권한 요청·답 대기·자동 수정 사람 판단·PR 검토, 카드마다 주 동작 하나) 아래 진행 중 → 대기·막힘(같은 원인 셋 이상은 한 줄로 묶음) → 읽지 않은 결과(접힘) → 끝난 일(접힘)을 놓는다. 전체 탭에서는 카드마다 출처 칩을 단다. 모든 카드는 키보드로 열리고, 열면 서랍이 목록 옆에 서고 목록은 한 줄로 접힌다(좁은 폭에서는 배경을 가리고 뜬다). 카드 한 장에는 상태 배지가 하나다.

- **작업**: `claude agents --json --all`과 세션 대화 기록으로 상태를 보여 준다. 쉬는 세션의 마지막 답이 질문으로 끝나면(마지막 문장만 보고, 사람이 그 뒤에 답하지 않았을 때만 — `scripts/board/asks.py`) '답 대기'로 지금 할 일에 올리고 그 질문 문장을 카드에 보인다. git 저장소가 아닌 작업 폴더는 사이드바에서 저장소로 세지 않는다. 대화 보기(위로 올리면 이전 대화), 입력 보내기(백그라운드 세션은 멈춘 뒤 같은 ID로 이어 가기, Orca 터미널의 대화형 세션은 그 터미널에 입력), 질문(AskUserQuestion) 답 버튼, 권한 요청 허용/거부, 읽음 처리, 끝난 세션 정리.
- **하네스 동작**: 자동 harvest·sync 실행 기록, 대기 중인 harvest(지금 돌리기), 정기 실행, 워크플로 러너, 자동 적용 규칙. 사람 확인이 필요한 PR은 호스트에서 병합·거절되면 완료로 내린다.
- **하네스 설정**: 값을 바꾸는 행만 둔다 — 기본값과 다른 값에만 "기본값과 다름" 표시, 기본과 다르게 둔 저장소만 펼쳐 두고 나머지는 접음, 여러 저장소에 같은 경고는 위에 한 줄. `~/.ai-harness/config`의 개인 자동화 단계(`HM_DELIVERY_LEVEL`·`HM_DELIVERY_LEVEL_REPOS`), 자동 harvest·sync 실행/병합과 하루 상한을 바로 쓴다(다른 줄은 보존). 기준 브랜치·배포·스모크 명령 같은 저장소 사실은 `harness.json`을 직접 고치지 않고 그 저장소에서 `/ai-harness:harness-init` 설정 변경 세션을 띄워 draft PR로 낸다.
- **하네스 효과**: 저장소마다 `scripts/impact.sh compare`(`/ai-harness:harness-impact`와 같은 집계)를 보드가 뒤에서 하루 한 번 돌려 `~/.ai-harness/board/impact/<저장소>/<날짜>.json`에 두고 보여 준다. 화면을 열 때 오늘 결과가 없으면 계산을 시작하고 지난 결과를 먼저 보여 준다. "다시 계산"은 오늘 결과가 있어도 새로 돌린다. 실패(설치일 모름 exit 3 등)는 이유와 함께 보이고 그날은 자동으로 다시 돌리지 않는다. 맨 위에 전체 한 줄과 저장소별 한 줄 상태(효과 확인·엇갈림·재발/악화·관찰 중·데이터 부족·최근 세션 없음, 신호가 없으면 왜 모르는지)를 두고, 최근 세션이 없거나 계산하지 못한 저장소는 아래에 접는다. 저장소마다 세션당 교정·사실 부족의 설치 후 주별 추세(줄고 있음·비슷함·늘고 있음·데이터 부족)가 주 지표이고, 설치 전후 비교는 표본이 충분할 때만 숫자로, 아니면 "비교 불가 — 설치 전 기록 없음"처럼 이유를 보인다. 상태·추세·비교 가능성은 `impact.sh view`(`scripts/impact-assess.jq`)가 정한 값이고 `/harness-impact` 리포트와 같다 — 보드는 규칙을 갖지 않는다. 개선은 펼쳐 보는 줄(최신순, 규칙 제거는 따로)이고 판정 배지는 리포트와 같은 낱말(사라짐·줄어듦·재발·판단 보류·기준 없음·판정 안 함)이다. 제목은 요약의 첫 문장, 원문·근거는 줄을 펼친 곳에 둔다. 카드의 판정은 `/harness-impact`가 그 저장소에서 마지막으로 맞춘 매칭을 그날까지의 세션에 다시 쓴 값이다(`impact.sh view`) — 보드는 같은 유형인지 맞추지도, 판정 규칙을 갖지도 않는다. 매칭이 없으면 반영 뒤 관찰 세션이 5개 미만은 "판단 보류", 아니면 "판정 안 함"이고, 판정을 채우려면 그 저장소에서 `/ai-harness:harness-impact`를 돌리라고 안내한다 — LLM 토큰이 드는 선택 동작이라 보드가 자동으로 돌리지 않는다(설치 전 세션 정리도 같다). 보드 계산은 bash·jq 집계뿐이다. "전체 리포트 열기"는 `impact.sh render`로 오프라인 리포트를 `~/.ai-harness/reports/`에 만들어 연다. 읽기 전용 — 개선을 되돌리거나 하네스를 고치지 않는다.
- **자동 수정(목록 카드)**: `autofix-auto.sh status`의 에러 시그니처마다 카드 한 장 — 상태 배지 하나(사람 판단·PR 검토·수정 중·배포 대기·재발 관찰 중·재발·실행 실패·해결·건너뜀), 로그 원문 대신 사람 말로 다듬은 제목(시각·로그 수준·추적 ID·해시·로거 위치를 걷어 냄, 원문은 서랍에), 감지 건수. 카드를 열면 서랍에 단계·원인 분석 요약(실행 로그의 결과 텍스트, 비밀값·홈 경로 가림)·원문 제목·모니터링 링크·로그·PR이 보인다. "세션으로 열기"로 띄운 세션은 그 에러 카드에 합쳐져("이어 보는 세션") 따로 카드가 생기지 않는다. 상태 열: 넘김(`left_for_user`)·포기·실패·PR 검토 대기 → 사람 필요, 수정 중·검증 중 → 진행 중, 재발 → 대기, 해결·PR 닫힘·그 밖의 건너뜀 → 완료. PR이 호스트에서 병합되면 진행 중, 닫히면 완료로 옮긴다(`prstate`). 사람 필요 카드의 "세션으로 열기"는 그 저장소에서 원인 요약을 넘긴 세션을 띄운다(사람이 누를 때만). 상태 파일을 잃고 실행 기록에만 남은 실행도 카드로 보인다.
- **자동 수정(탭 위 한 줄 상황·후보)**: 무인 실행 켜짐/꺼짐 · 오늘 실행 수/상한 · 누적 비용 · 최근 실행 결과와 하네스 설정으로 가는 버튼, 지금 할 일 아래 **후보**(저장소마다 "후보 조회" — `autofix-auto.sh candidates`, 버튼으로만). 후보 줄을 펼치면 왜 후보인지·서비스·처음/마지막 본 때·관련 세션·모니터링 링크·원문 제목이 보이고, "원문·스택 불러오기"(`monitor-fetch.sh detail`, 후보 조회 때 남긴 조회 정보로 다시 찾음, 비밀값 가림)는 누를 때만 돌고 결과를 남긴다. 이미 상태 기록이 있는 에러는 후보에 다시 싣지 않고 카드가 말한다. 맨 아래에는 카드가 보여 주지 않는 최근 기록(건너뛴 이유·상태 기록·검증 오류)만 접어 둔다.
- **자동 수정(하네스 설정의 "자동 수정" 탭 — 저장소별 연결 → 개인 설정 순)**: 연결은 문제 있는 저장소만 행으로 보이고(나머지는 접음), 대상 저장소는 켜고 끄는 칩이다. `/ai-harness:autofix`의 저장소별 준비 상태(`scripts/monitor-fetch.sh describe` — 요청 없이 monitor 설정 출처(개인 로컬 파일·저장소 manifest·없음)·provider·query 요약·자격증명 있음/없음만, 값은 싣지 않음)와 무인 실행 대상 여부를 보여 준다(`autofix-auto.sh configure`로 대상 여부를 읽는다). 접근 확인(`monitor-fetch.sh check`, 종료 코드 4 = 자격증명·설정 오류, 5 = 설정 없음)은 모니터링 도구 API를 부르므로 버튼으로만 돌리고 결과를 `~/.ai-harness/board/autofix/`에 남긴다 — 화면을 열어도 다시 부르지 않는다. 설정이 없거나 틀린 저장소는 "설정하기"로 그 저장소에서 `/ai-harness:autofix setup` 세션을 띄운다(보드는 monitor 파일을 쓰지 않는다). 하네스 설정의 "자동 수정" 탭(무인 실행·대상 저장소·sweep 주기·하루 상한·에러당 PR 상한·실행당 예산 — 주기·하루 상한·예산은 직접 입력도, 하루 상한·예산은 "제한 없음"도 받고 그때 비용 경고를 보임)은 `autofix-auto.sh configure`로만 쓰고, 주기를 바꾸면 `schedule.sh install-autofix`(sweep 전용 에이전트만 등록·해제, backfill은 그대로, 등록 즉시 실행 없음)와 `status` 결과를 보여 준다. 화면 보기·상태·검증은 LLM이 들지 않고, 수정 실행은 에러마다 LLM 세션이라 비용이 든다 — 보드는 수정 실행(sweep)을 시작하거나 PR을 병합하지 않는다.
- **끝난 일 정리**: 끝난 일 칸 머리의 "끝난 일 정리…"가 범위(하루·일주일 넘은 것, 전체)별로 정리할 항목과 각각 일어날 일(숨김 / 쉬는 세션 닫기 / worktree 삭제 가능·불가와 이유)을 미리 보이고, 확인하면 `POST /cleanup-bulk`로 카드별 정리(`cleanup`)를 한꺼번에 돌린다. 기본은 목록에서 숨기기 + 쉬는 세션 닫기이고, worktree 삭제는 체크박스를 켰을 때만 기존 확인(변경·올리지 않은 커밋·다른 살아 있는 세션 없음)을 통과한 것만 지운다(강제 없음). 작업 중·답 대기·권한 대기 세션은 대상이 아니고 대화 기록은 지우지 않는다. 하네스 동작·자동 수정의 끝난 항목은 숨기기만 하고, 그 항목에 새 일이 생기면 다시 보인다. 같은 정리가 동시에 두 번 돌지 않는다. 숨긴 항목은 "숨긴 항목 N개"(`GET /hidden`, `POST /hidden/restore`)에서 다시 보이게 한다 — 닫은 세션·지운 worktree는 되돌리지 않는다.
- 보드는 다른 세션의 질문·권한에 **사람 없이 답하지 않는다**. 대화 기록(transcript)은 지우지 않는다. 세션 정리에서 worktree는 변경·원격에 없는 커밋·다른 살아 있는 세션이 없을 때만 지우고 강제 삭제는 하지 않는다.
- Orca는 선택이다. 없으면 세션 묶음과 대화형 터미널 입력만 빠진다.

## 권한 요청을 보드로 받기 (선택)

보드에서 권한 요청을 허용/거부하려면 PermissionRequest 훅이 필요하다. 이 스킬은 훅을 몰래 연결하지 않는다 — 사용자가 원하면 `/ai-harness:setup`의 자동화 옵션(8-2)으로 연결한다. 훅은 보드가 떠 있고 누군가 보드를 보고 있을 때만 요청을 넘기며, 아니면 아무것도 출력하지 않아 평소처럼 터미널에서 묻는다. headless 세션(`claude -p` — 워크플로 러너·자동 harvest·autofix 같은 자동 실행)의 요청은 보드로 넘기지 않는다 — 답할 사람이 없는 세션을 붙잡으면 그 실행이 멈추므로, Claude Code가 평소처럼 바로 거부하고 세션이 이어 간다.

## 보안

서버는 `127.0.0.1`에만 묶인다. 실행마다 새 URL 토큰을 만들고, 모든 요청의 Host(DNS rebinding 방어), POST의 Origin을 검사한다. 브라우저에서 명령 문자열을 받지 않고 항목별로 허용된 작업만 서버가 인자를 만들어 실행한다. 권한 훅 엔드포인트는 별도 토큰을 쓰며, 그 토큰과 주소는 `~/.ai-harness/board/server.json`(0600, 서버 종료 시 삭제)에만 있다.
