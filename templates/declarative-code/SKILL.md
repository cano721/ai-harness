# 선언적 코드 판단

> 선언적 코드란 패러다임이 아니라 **추상화 수준**이다 — "어떻게(how)"를 한 칸 아래로 내리고 "무엇(what)"만 남긴 코드. (Toss, [선언적 코드 작성하기](https://toss.tech/article/frontend-declarative-code))

프로젝트에 고유한 규칙(디자인 시스템 이름, 승격 기준, escape hatch 순서)이 `AGENTS.md`나 `.ai-harness/docs/`에 있으면 그쪽이 우선한다. 없으면 아래 기본값을 쓴다.

## 전제 두 가지

**1. 선언/명령은 이분법이 아니라 스펙트럼이다.** `for...of`는 iterator 수동 조작보다 선언적이고, `sum(nums)`은 `for...of`보다 선언적이다. 모든 코드는 사다리의 한 칸에 있고, "선언적으로 만든다"는 칸을 올리는 행위다. 따라서 질문은 "선언적인가?"가 아니라 **"몇 칸까지 올릴 것인가?"**다.

**2. 선언은 엔진 없이 성립하지 않는다.** "어떻게"를 감추려면 그걸 대신 수행하는 엔진이 있어야 한다 — React 렌더러(UI = f(state)), SQL 옵티마이저, K8s reconciliation loop, 프론트엔드라면 디자인 시스템 컴포넌트와 테마 토큰. 엔진이 없는 선언은 추상화가 아니라 미구현이다.

## 판단: 추상화를 올릴까? — 세 가지 질문

한 칸 올리기 전에(공용 컴포넌트 승격, 커스텀 variant, 훅 추출, 래퍼 도입) 셋을 순서대로 묻는다. **하나라도 아니오면 올리지 않는다.**

### Q1. 수정 예측 — 감출 "어떻게"가 모든 사용처에서 같은가?

같은 것이 한꺼번에 바뀌어야 추상화가 이득이다. 사용처마다 요구가 다른 걸 억지로 올리면 "어떻게"가 사라지는 게 아니라 **props로 다시 노출**된다(props 20개짜리 `<SignUpForm>` 문제).

- O: 상태 배지의 색 — 어디서든 같아야 하고 바뀌면 전부 바뀐다 → 테마 variant로 승격
- X: 도메인 카드 — 색·배치가 리뷰마다 뒤집히는 동안은 스토리/사용처에 둔다. 요구가 굳은 뒤에 승격한다

판단이 어려우면 기본 승격 규칙을 따른다: **사후에, 두 번째 사용처가 실제로 생겼을 때.** 프로젝트에 shared 승격 원칙이 문서화돼 있으면 그쪽이 우선한다.

### Q2. 엔진 신뢰 — "어떻게"의 제어를 포기해도 되는가?

올린 뒤에는 엔진이 결정한다(렌더링 방식, 실행 계획, 스타일 산출). 엔진이 검증돼 있고 그 결정에 개입할 일이 없어야 한다. 성능·동작을 미세 제어해야 하는 지점이면 낮은 칸에 남긴다 — SQL도 결국 쿼리 플랜을 읽게 되는 자리가 있다.

### Q3. 누수 대비 — 샜을 때 열어볼 수 있는가?

**"사소하지 않은 모든 추상화는 어느 정도 샌다"** (Spolsky, 새는 추상화의 법칙). 추상화는 일하는 시간은 아껴도 배우는 시간은 못 아낀다. 올리기 전에 확인한다:

- **escape hatch가 있는가.** 기본 사다리: 컴포넌트 prop → `style`/`className` + 토큰 → CSS 파일(값은 토큰). 사다리 밖으로 나가야만 되는 요구가 보이면 추상화가 틀렸다는 신호다.
- **근거가 기록되는가.** 감춘 "왜"는 주석·스토리 doc으로 남긴다. 새는 순간 안을 설명할 문서가 보험이다.

## 설계: 컴포넌트 API — 사용처가 명세가 되게

Q1~Q3을 통과해 올리기로 했으면, 인터페이스는 이 기준으로 깎는다: **props 시그니처가 사용처에서 읽히는 전부다.** `<후보카드 후보={x} 선택됨={y} on선택={...} on제안={...} />`만 읽어도 이 컴포넌트가 무엇을 보여주고 무슨 일이 일어날 수 있는지 드러나야 한다. 렌더 트리가 곧 명세가 되는 것 — 이게 컴포넌트 층위에서의 "선언적"이다.

| 뚫는 것 | 규칙 | 근거 |
|---|---|---|
| 일어나는 일 | `on` + **도메인 동사**: `onBookmark`, `on제안`. DOM 이벤트명(`onClick`)은 의미가 정말 "클릭 그 자체"일 때만. 인터랙션이 둘 이상이거나 의미가 앱 개념이면 도메인 이름으로 승격 — 트리거가 바뀌어도(클릭→단축키) 부모는 무관해진다 | [react.dev의 `onPlayMovie`](https://react.dev/learn/responding-to-events) |
| 상태 | `x` / `defaultX` / `onXChange` 트리플 — prop 이름만으로 controlled/uncontrolled가 판별된다. `onChange`는 `value` 전용, 다른 상태는 `on<상태>Change`. boolean은 `is` 접두사 | [Spectrum Guidelines](https://github.com/adobe/react-spectrum/blob/main/specs/api/Guidelines.md), Radix `open/defaultOpen/onOpenChange` |
| 모양 | 상호배타 상태는 boolean N개가 아니라 단일 `variant`/`status` enum — `<Alert success warning>`이라는 불가능한 조합을 타입으로 막는다 | [Make Impossible States Impossible](https://kentcdodds.com/blog/make-impossible-states-impossible) |
| 내용·구조 | 사용처마다 다른 마크업은 `renderX`/설정 props가 아니라 **children 합성** — 화면이 코드에 그대로 보여야 한다. 단 이벤트·데이터는 props가 맞다; 역할 분담이다 | [compound components](https://kentcdodds.com/blog/compound-components-with-react-hooks) |
| (숨기는 것) | **시그니처에 없는 일은 안에서 하지 않는다.** 페칭·네비게이션·로깅·전역 상태 변경을 이름·props·반환에 안 드러나게 숨기지 말 것. 숨겨야 하면 이름에 새긴다(`getWithAuth`) | [숨은 로직 드러내기](https://frontend-fundamentals.com/code-quality/code/examples/hidden-logic.html) — `frontend-fundamentals` 스킬의 예측 가능성 축 |

액션을 prop으로 뚫는 것과 Q1은 같은 판의 양면이다: 사용처마다 갈리는 **결정**(눌렀을 때 뭘 할지, 안에 뭘 그릴지)은 밖에 남기고(이벤트 props·children), 어디서나 같은 **표현**(배지 색)만 안으로 흡수한다. `SignUpForm`이 props 20개가 되는 건 이 방향을 거꾸로 잡아서다 — 갈리는 결정을 옵션 props로 흡수하려 했기 때문.

## 디버깅: 추상화가 샐 때

선언 층에서 원인이 안 보이면 **한 칸 아래로 내려가서** 본다. 증상별 진입점:

| 증상 | 내려갈 곳 |
|---|---|
| 같은 선언인데 다르게 보인다 | 엔진의 조건 차이 — 크기·상태·컨텍스트. (예: 같은 색 토큰이 작은 사이즈에서 연해 보임 = 렌더링 획 두께 문제, 색 문제 아님) |
| 스타일이 안 먹는다 | 엔진의 우선순위 — 스타일 엔진 vs 테마 오버라이드 vs `style` prop 순서. 디자인 시스템 패키지의 실제 구현(`node_modules/<pkg>/src/`)을 연다 |
| 선언에 없는 동작이 나온다 | 엔진의 기본값 — prop을 생략했을 때 엔진이 채우는 값. 컴포넌트 타입 정의나 문서의 Default 열을 본다 |

내려가서 알아낸 것은 그 자리에 주석으로 남긴다 — 다음 사람이 같은 층을 다시 파지 않게.

## 선언 사다리

```
높음   테마 variant/토큰      전역 불변 규칙
  │    디자인 시스템 컴포넌트   엔진이 "어떻게"를 수행하는 층
  │    스토리/사용처의 조합     굳는 중인 패턴의 대기소
  │    style + 토큰           escape hatch 1
낮음   CSS 파일 + 토큰         escape hatch 2 (최후)
```

새 패턴은 아래 칸에서 시작해 Q1~Q3을 통과할 때마다 한 칸씩 올린다. 하드코딩 hex/px는 어느 칸에도 없다. 프로젝트의 실제 사다리(디자인 시스템 패키지 이름, 테마 이름, 스토리 위치)는 `AGENTS.md`나 `.ai-harness/docs/`에 적어 두고 여기서는 그 문서를 읽는다.
