# 네이티브 UI 검토

검토의 계약은 웹과 같다. 단계(요청 분석 → 디자인 시스템 확인 → 디자인 시스템 검토 → 사용자 UX 검토 →
수정과 재검증 → 근거와 한계 보고), 판정(`verified` / `issues` / `unverified`), 주요 문제의 정의, 거짓 통과
목록은 [UI 검토 계약](references/ui-review-contract.md)을 그대로 따른다. 이 Skill은 그 계약을 네이티브
앱에 적용할 때 바뀌는 것만 담는다.

- 무엇을 보는가: [네이티브 체크리스트](references/checklist.md)
- 플랫폼마다 무엇이 다른가, 어떻게 띄우고 찍는가: [플랫폼 참조](references/platforms.md)
- 시안이 있을 때: [시안 처리 규칙](references/design-handoff.md)

## 무엇이 우선하는가

1. 프로젝트 규칙: `AGENTS.md`, `.ai-harness/docs/ui.md`(대상 플랫폼, 빌드·실행 명령, 시뮬레이터·에뮬레이터
   기기, 로그인·시드 방법, 지원 크기·테마·글자 크기), 프로젝트 디자인 문서, 의미 토큰, 공통 컴포넌트
2. 이 Skill과 UI 검토 계약
3. 플랫폼 지침(Apple Human Interface Guidelines, Material Design 3)과 WCAG 2.2. 수치마다 출처를 적었다
4. 외부 디자인 Skill(설치돼 있을 때만, 선택 보조)

크로스플랫폼(React Native·Flutter) 앱이 iOS와 Android에서 같은 모양을 쓸지, 각 플랫폼의 관용 표현을
따를지는 프로젝트 결정이다. 어느 쪽이든 각 OS가 사용자에게 보장하는 것(안전 영역, 뒤로 가기, 글자 크기,
스크린리더, 감소 모션)은 지킨다.

## 계약을 네이티브로 읽는 법

| 계약의 말 | 네이티브에서 |
|---|---|
| 브라우저로 열고 조작한다 | 시뮬레이터(iOS)·에뮬레이터(Android)에 빌드를 설치하고 실행해 탭·스와이프·하드웨어 뒤로 가기·키보드로 조작한다 |
| 뷰포트(데스크톱·모바일) | 기기 크기 등급: 작은 폰, 큰 폰, 앱이 지원하면 태블릿·폴더블·가로. 레이아웃은 기기 이름이 아니라 크기 등급(iOS size class, Android window size class)으로 나눈다 |
| 테마 | 라이트·다크, 그리고 큰 글자(iOS Dynamic Type, Android 글꼴 크기) |
| URL | 화면 경로(딥 링크가 있으면 그 주소, 없으면 진입 탭·버튼 순서) |
| 캡처 | 시뮬레이터·에뮬레이터 스크린샷. 찍는 명령은 [플랫폼 참조](references/platforms.md) |
| 기준 화면 | 프로젝트의 컴포넌트 카탈로그 화면·스토리북(있을 때). 없으면 같은 역할의 이웃 화면 |
| 시안 처리 규칙의 px | pt(iOS)·dp(Android). 허용 오차 수치는 그대로, 터치 영역 하한(24px)은 이 Skill 체크리스트 4번(44pt·48dp)으로 읽는다 |
| 계약 안의 `references/checklist.md` | 이 Skill의 [웹 공통 체크리스트](references/web-checklist.md)와 [네이티브 체크리스트](references/checklist.md) |
| 계약 안의 `references/design-skills.md`(디자인 스킬 지도) | 웹 전용이라 이 Skill에 배포하지 않는다. 링크는 무시한다 — 지도의 웹 디자인 스킬은 네이티브 화면을 주도하지 않고, 외부 디자인 Skill은 위 우선순위 4번(선택 보조)으로만 쓴다 |
| 계약 안의 `references/web-interface-guidelines.md`(웹 인터페이스 가이드라인) | 웹 코드용 규칙이라 이 Skill에 배포하지 않는다. 링크는 무시한다 — 네이티브 화면은 [네이티브 체크리스트](references/checklist.md)와 플랫폼 지침으로 본다 |
| 키보드로 완주 | 스크린리더(VoiceOver·TalkBack)로 완주. 외부 키보드·태블릿을 지원하면 키보드도 |

## 증거

- 캡처는 시뮬레이터·에뮬레이터에서 찍는다. 웹 브라우저로 띄운 React Native Web·Flutter Web 화면은 네이티브
  화면의 증거가 아니다.
- 시나리오마다 기본 상태, 다크, 큰 글자 캡처를 남긴다. 지원하는 기기 크기 등급마다 따로 찍는다.
- 보고의 "환경"에 기기 이름·OS 버전과 **증거 출처**(시뮬레이터 / 에뮬레이터 / 실기기)를 적는다. 시뮬레이터는
  화면 폭과 설정 조합을 넓게 보지만, 손으로 잡는 자세·실제 제스처 감각·성능·카메라나 센서는 실기기에서만
  확인된다. 실기기로 보지 못한 항목은 미검증으로 적는다.
- 빌드·설치·실행 도구(Xcode·`xcrun simctl`, Android SDK·`adb`, Flutter·Expo CLI)가 없거나 앱을 띄우지 못하면
  `unverified`다. 테스트 통과나 코드 확인으로 대신하지 않는다.

## 거짓 통과 (네이티브에서 더 보는 것)

계약의 거짓 통과 표에 더해 아래도 통과 근거가 아니다.

| 겉보기 근거 | 놓치는 것 | 대신 확인할 것 |
|---|---|---|
| 웹 미리보기·브라우저 캡처가 있다 | 안전 영역, 시스템 바, 뒤로 가기 제스처, 네이티브 컨트롤 | 시뮬레이터·에뮬레이터 캡처 |
| 기본 글자 크기에서 잘 보인다 | 큰 글자에서 잘리거나 겹치는가 | 큰 글자 설정 캡처 |
| `accessibilityLabel`·`contentDescription`·`Semantics`가 코드에 있다 | 스크린리더가 실제로 그 이름·역할·상태를 읽는가 | VoiceOver·TalkBack으로 시나리오를 따라간 기록 |
| 라이트 모드 캡처만 있다 | 다크에서 하드코딩한 색이 사라지거나 대비가 무너지는가 | 다크 캡처 |
| 한 플랫폼에서 확인했다 | 다른 플랫폼의 뒤로 가기·안전 영역·시스템 컨트롤 | 지원하는 플랫폼마다 따로 확인 |
