# 네이티브 UI 체크리스트

iOS·Android 앱 화면 기준이다. 항목마다 **시뮬레이터·에뮬레이터에서 무엇을 보면 되는지**를 적었다. 웹
체크리스트(UI 검토 계약의 `references/checklist.md`)의 발견 가능성·일관성·상태·행동과 결과·입력과 오류
항목은 네이티브에도 그대로 적용한다 — 이 문서는 플랫폼이 바꾸는 것만 더한다. 프로젝트에 해당 플랫폼·크기·
테마가 없으면 건너뛰고 이유를 남긴다.

출처 표기: HIG = Apple Human Interface Guidelines, M3 = Material Design 3, WCAG = WCAG 2.2. 프로젝트 문서가
다르게 정했으면 프로젝트 문서를 따른다.

## 배치

1. **안전 영역** — 노치·다이내믹 아일랜드·상태 바·홈 표시줄·제스처 내비게이션 영역·둥근 모서리 아래에 누르는
   요소나 읽어야 할 글자가 없다. 배경은 화면 끝까지 그려도 되지만 콘텐츠는 안전 영역 안에 있다(HIG Layout,
   Android edge-to-edge 인셋).
2. **크기 등급별 배치** — 레이아웃이 기기 이름이 아니라 크기 등급으로 바뀐다(iOS size class, Android window
   size class: compact < 600dp ≤ medium < 840dp ≤ expanded). 태블릿·가로·폴더블을 지원하면 폰 화면을
   늘린 것이 아니라 그 폭에 맞는 배치(두 열, 내비게이션 레일)를 쓴다.
3. **긴 목록** — 긴 목록은 보이는 행만 그리는 목록(`List`·`LazyColumn`·`RecyclerView`·`FlatList`·
   `ListView.builder`)을 쓴다. 수백 행에서 스크롤이 끊기지 않는다.

## 터치와 제스처

4. **터치 영역** — 누르는 대상은 iOS 44×44pt(HIG), Android 48×48dp(M3) 이상이고 이웃 대상과 8dp 이상
   떨어져 있다. 보이는 아이콘이 작으면 터치 영역을 넓힌다. 이보다 작아 실제로 잘못 눌리면 주요 문제다.
5. **제스처에 대안이 있다** — 스와이프 삭제·끌어서 순서 바꾸기·길게 누르기 메뉴는 보이는 버튼이나 메뉴로도
   할 수 있다(WCAG 2.5.7). 스크린리더 사용자는 사용자 지정 동작(accessibility actions)으로 같은 일을 한다.
6. **시스템 제스처를 빼앗지 않는다** — 화면 가장자리 스와이프(iOS 뒤로 가기, Android 뒤로·홈 제스처)가 앱의
   가로 스와이프에 막히지 않는다.

## 탐색

7. **뒤로 가기가 상태를 지킨다** — 뒤로 가기(iOS 가장자리 스와이프·뒤로 버튼, Android 시스템 뒤로)로 돌아오면
   이전 화면의 스크롤 위치·입력값·선택한 탭이 남아 있다. 작성 중인 내용을 잃는 뒤로 가기에는 확인이 있다.
8. **모달은 닫는 길이 둘이다** — 시트·모달에 보이는 닫기(취소·완료) 버튼이 있고, 플랫폼 제스처(아래로 쓸어
   닫기, Android 뒤로)로도 닫힌다. 저장하지 않은 입력이 있으면 닫기 전에 묻는다.
9. **최상위 탐색이 플랫폼 모양이다** — 최상위 구역은 탭 바(iOS)·내비게이션 바(Android)로, 계층은 내비게이션
   스택으로 간다. 개수와 넓은 화면 처리는 [플랫폼 참조](platforms.md)를 따른다.

## 글자와 색

10. **글자 크기 설정을 따른다** — iOS Dynamic Type 텍스트 스타일, Android `sp` 단위를 쓴다. 가장 큰 접근성
    글자 크기(iOS AX 크기, Android 글꼴 크기 최대)에서 글자가 잘리거나 겹치지 않고, 필요하면 줄바꿈·세로
    배치로 바뀐다. 고정 높이 안에 글자를 가두지 않는다.
11. **의미 색과 다크 모드** — 색은 시스템 의미 색이나 프로젝트 의미 토큰에서 온다. 라이트·다크를 각각
    렌더링해서 하드코딩한 색이 배경에 묻히지 않는지 본다.
12. **대비와 색 단독 상태** — 본문 글자 4.5:1, 큰 글자·아이콘·입력 테두리·포커스 표시 3:1 이상(WCAG 1.4.3,
    1.4.11). 선택·오류 상태를 색만으로 구분하지 않는다(WCAG 1.4.1).

## 보조기술

13. **이름·역할·상태** — VoiceOver·TalkBack이 누르는 요소마다 이름(무엇인가), 역할(버튼·스위치·탭), 상태(선택됨·
    꺼짐·펼쳐짐)를 읽는다. 아이콘만 있는 버튼에도 이름이 있다. 장식 이미지는 읽지 않는다.
14. **읽는 순서와 묶음** — 스크린리더가 보이는 순서대로 읽고, 한 카드의 제목·값·버튼이 흩어지지 않게 묶인다.
15. **상태 알림** — 저장 완료·오류·결과 건수처럼 포커스가 옮겨 가지 않는 변화는 스크린리더에 알린다(iOS
    accessibility notification, Android live region·announcement, Flutter `SemanticsService`).

## 모션과 피드백

16. **감소 모션** — iOS "동작 줄이기", Android "애니메이션 삭제"를 켜고 시나리오를 다시 본다. 미끄러짐·확대·
    패럴랙스는 크로스페이드나 즉시 전환으로 바뀌고, 상태를 알려 주는 변화와 눌림 피드백은 남는다.
    콘텐츠가 사라지거나 조작할 수 없으면 주요 문제다.
17. **전환이 조작을 막지 않는다** — 화면 전환·시트 등장 중에도 뒤로 가기와 다음 탭이 먹는다. 제스처로
    시작한 전환은 도중에 손을 떼거나 되돌릴 수 있다.
18. **오래 걸리는 일은 보인다** — 300ms를 넘을 수 있는 작업은 처리 중 표시가 있고, 그 사이 같은 행동을 다시
    누를 수 없다. 진행을 모르면 진행률을 지어내지 않는다. 오프라인·권한 거부·서버 오류를 각각 다른 문구로
    안내하고 다시 시도할 길이 있다.

## 증거

19. **캡처 조합** — 시나리오마다 기본 상태·다크·큰 글자를, 지원하는 플랫폼과 크기 등급마다 찍었다. 찍는
    명령은 [플랫폼 참조](platforms.md)에 있다.
20. **출처 표기** — 캡처마다 기기·OS 버전·출처(시뮬레이터 / 에뮬레이터 / 실기기)를 적었다. 실기기에서만 확인되는
    것(잡는 자세, 제스처 감각, 성능, 센서)은 미검증으로 남겼다.
