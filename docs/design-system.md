# ai-harness 디자인 규칙

ai-harness가 사용자에게 보여 주는 단일 HTML 화면(보드, 하네스 효과 리포트 — 서버나 빌드 없이 열리고 오프라인에서도 동작한다)의 디자인 규칙이다. 값은 여기에 적지 않는다 — 값은 토큰 파일에만 있고, 이 문서는 토큰 이름과 규칙을 말한다. 필수 절 13개의 제목과 순서는 `design-audit`가 채점 입력으로 읽으므로 바꾸지 않는다.

## 메타

- 상태: draft
- 원천: 기존 코드 추출(`scripts/board/template.html`, `skills/harness-impact/report-template.html`의 CSS 변수와 반복 패턴) + 새로 설계(독립 디자인 리뷰 2026-11-10의 지적, 공개 디자인 명세 6개 참고), 2026-11-10
- 토큰 파일: `docs/design-system/tokens.css` (원본). 공용 부품 CSS는 `docs/design-system/components.css`, 대비 검사 쌍은 `docs/design-system/contrast-pairs.tsv`
- 기준 화면: `docs/design-system/reference.html` — 브라우저에서 파일을 바로 연다(서버 없음). `?theme=light|dark`, `?drawer=1`로 상태를 고정해 열 수 있다
- 테마: light, dark — 전환 방식: OS 설정(`prefers-color-scheme`)을 따르고 `<html data-theme="light|dark">`가 있으면 그쪽이 이긴다
- 뷰포트: 최소 `--size-viewport-min`, 중단점 `--breakpoint-narrow`·`--breakpoint-wide`
- 확인 대기: 8 — 목록은 이 문서를 만든 PR #288(이슈 #287) 본문의 "결정 사항"에 있다
- 적용 범위: 보드와 리포트에는 토큰만 이어 두었다(기존 변수 이름 유지). 부품을 공용 부품으로 바꾸고 화면을 재구성하는 일은 다음 단계다
- 밖으로 나가는 요청: 글꼴 파일 하나(아래 `## 타이포그래피`). 그 밖에는 화면이 밖에서 아무것도 불러오지 않는다 — `tests/run.sh`가 이 URL 하나만 허용한다
- 사본 규칙: 보드·리포트·기준 화면은 단일 HTML이라 토큰·부품 CSS를 파일 안에 사본으로 싣는다. 원본을 고친 뒤 `scripts/design-system.sh sync`로 맞추고, `check`와 `contrast`는 `tests/run.sh`가 돌린다

## 원칙

1. **색 하나에 뜻 하나.** 상태 색 여섯 가지는 각각 한 가지 뜻에만 쓴다. 빨강(`--color-danger`)은 실제 실패에만 쓴다 — 경고·기본값·강조에 쓰지 않는다. 강조와 포커스는 색이 아니라 명도(`--color-accent`, `--color-focus`)로 한다.
2. **눌리는 것처럼 보이면 눌린다.** hover·손가락 커서·화살표는 실제로 반응하는 요소에만 붙인다. 반응하는 요소는 전부 키보드로 닿고 포커스 표시가 보인다.
3. **한 항목에 상태는 한 번.** 카드·줄 하나에 배지는 하나다. 같은 상태를 띠·점·배지로 겹쳐 말하지 않고, 화면이 보여 주는 상태는 시스템이 아는 실제 상태와 같다.
4. **같은 말은 한 번.** 같은 원인으로 반복되는 항목은 묶음 한 줄로 접고, 같은 경고는 화면 위 알림 줄 하나로 올린다. 주 버튼은 한 영역에 하나다.
5. **기본은 조용하게.** 기본값인 설정, 끝난 일, 데이터가 부족한 칸은 강조하지 않거나 접는다. 사람이 지금 할 일이 화면 맨 위에 온다.

## 레이아웃

중단점과 폭은 토큰 이름으로 부른다. 미디어 쿼리는 CSS 변수를 못 쓰므로 `components.css`가 같은 값을 직접 적는다.

| 분류 | 알아보는 법 | 예 |
|---|---|---|
| 목록 | 상태별로 모은 항목(카드·줄)과 필터 탭, 항목마다 동작 | 보드 "작업 현황" (전체·작업·하네스 동작·자동 수정 탭) |
| 요약 | 지표 타일·표·차트로 결과를 읽는 화면, 조작이 적다 | 보드 "하네스 효과", 하네스 효과 리포트 |
| 설정 | 값을 바꾸는 행의 목록 | 보드 "하네스 설정" (탭별) |
| 상세 | 목록의 한 항목을 여는 서랍 | 보드의 세션·자동 수정 상세 |

공통 뼈대: 왼쪽 사이드바(`--size-sidebar`, `--color-surface-sunken`) + 본문. 본문의 가로 여백은 본문 컨테이너(`.ds-main`)가 갖는다(`--space-6`, 좁은 폭에서 `--space-4`). 페이지 머리(제목은 heading 역할, 주 동작은 오른쪽 끝) 아래 `--space-4`, 그 아래 탭, 그 아래 내용. 본문 최대 폭은 요약·설정에서 `--size-content-max`, 목록은 전체 폭을 쓴다.

- **목록**: 맨 위에 "지금 할 일"(사람이 답하거나 검토할 것만, 항목마다 주 동작 하나). 그 아래 진행 중 → 대기·막힘(원인별 묶음) → 완료(접힘). 열은 `.ds-columns`(열 최소 폭 `--size-column-min`)로 놓고, 탭은 같은 목록을 거르는 필터다. 항목 사이 `--space-2`, 열 사이 `--space-4`.
- **요약**: 한 단. 맨 위에 한 줄 결론, 그 아래 지표 타일, 그 아래 근거. 신호가 있는 것만 펼치고 "데이터 부족"은 접는다. 구획 사이 `--space-12`.
- **설정**: 한 단, 설정 행 목록. 값을 바꾸는 것만 둔다 — 운영 데이터(후보·이력)는 목록 화면에 둔다. 공통 경고는 행 위 알림 줄 하나.
- **상세(서랍)**: `--breakpoint-wide` 이상에서는 서랍(`--size-drawer`)이 목록 옆에 자리를 차지하고 목록의 열은 한 줄로 접힌다 — 카드를 좁히지 않는다. 그보다 좁으면 서랍이 `--color-backdrop`으로 배경을 가리고 목록 위에 뜬다.

## 색과 상태

화면과 부품은 의미 토큰만 쓴다. `--palette-*` 원시 값은 의미 토큰만 참조한다.

| 역할 | 토큰 | 쓰는 곳 |
|---|---|---|
| 페이지 바탕 | `--color-surface-page` | 본문 바탕 |
| 가라앉은 면 | `--color-surface-sunken` | 사이드바, 코드 블록 |
| 면 | `--color-surface` | 카드, 줄 목록, 입력 |
| 뜬 면 | `--color-surface-overlay` | 서랍, 토스트, 팝오버 |
| hover / 선택 | `--color-surface-hover` / `--color-surface-selected` | 눌리는 요소의 hover, 선택된 카드·값 |
| 글자 | `--color-text` / `--color-text-muted` | 본문 / 보조 정보. 글자 단계는 이 둘뿐이다 |
| 구획선 | `--color-border` | 카드·줄 사이, 눌리지 않는 것의 윤곽. 대비 요구 없음 |
| 조작 요소 윤곽 | `--color-border-control` | 버튼·입력·눌리는 카드·필터 칩의 윤곽. 바탕과 3:1 |
| 강조 | `--color-accent` / `--color-accent-hover`, 글자 `--color-text-on-accent` | 주 버튼, 선택 표시(탭 밑줄, 선택 윤곽, 켜진 필터 칩) |
| 포커스 | `--color-focus` | 포커스 윤곽 하나에만 |

**강조가 차지하는 넓이**: 강조는 무채색이다. 한 화면에서 `--color-accent`로 채운 면은 주 버튼과 켜진 필터 칩뿐이고, 주 버튼은 한 영역(카드·서랍 바닥·페이지 머리)에 하나다. 상태 색으로 채운 버튼은 없다.

**상태 색** — 각 상태는 글자·아이콘 / 옅은 면 / 경계 / 채운 면 네 토큰을 갖고, 항상 모양이 다른 아이콘과 글자가 같이 온다(색만으로 알리지 않는다).

| 상태 | 뜻(이 뜻에만) | 토큰 | 아이콘 |
|---|---|---|---|
| 사람 필요 | 사람이 답·허용·검토해야 진행된다 | `--color-attention`, `--color-attention-subtle`, `--color-attention-border`, `--color-attention-solid` | 종 |
| 진행 | 지금 돌고 있다 | `--color-progress`, `--color-progress-subtle`, `--color-progress-border`, `--color-progress-solid` | 도는 화살표 |
| 대기 | 차례·조건을 기다리거나 막혀 있다(사람이 당장 할 일은 아님) | `--color-waiting`, `--color-waiting-subtle`, `--color-waiting-border`, `--color-waiting-solid` | 모래시계 |
| 완료 | 끝났고 성공했다 | `--color-success`, `--color-success-subtle`, `--color-success-border`, `--color-success-solid` | 체크 |
| 실패 | 실제로 실패했다(오류, 재발, 저장 실패) | `--color-danger`, `--color-danger-subtle`, `--color-danger-border`, `--color-danger-solid` | 세모 느낌표 |
| 정보 | 상태가 아닌 사실(건너뜀, 기본값과 다름, 안내) | `--color-info`, `--color-info-subtle`, `--color-info-border`, `--color-info-solid` | i |

- 채운 면(`-solid`) 위 글자는 `--color-text-on-solid`만 쓴다. 흰색을 직접 쓰지 않는다 — 다크에서는 채운 면이 밝아지고 글자가 어두워진다.
- 상태 아이콘은 윤곽부터 서로 다르고, 닫기(가위표)·펼치기(화살표) 같은 조작 아이콘과 같은 도형을 쓰지 않는다.
- 채운 면은 개수 표시(`.ds-count`)와 상태 점(`.ds-dot`)에만 쓴다. 점은 배지나 열 제목 옆에서만 쓰고 혼자 상태를 알리지 않는다.
- 경고처럼 "주의해서 읽을 것"은 사람이 손써야 하면 사람 필요, 아니면 정보다. 실패가 아닌 것에 `--color-danger`를 쓰지 않는다.
- 차트 계열색은 이 표에 없다. 리포트의 계열색은 `dataviz` 스킬의 검증된 팔레트를 그대로 쓰고 상태 색과 섞지 않는다.

**선택·열림 표시**: 선택된 카드는 `--color-surface-selected` 바탕 + `--color-accent` 윤곽, 선택된 탭은 `--color-accent` 밑줄 + 굵은 글자, 선택된 값(선택 사다리)은 `--color-surface-selected` + `--color-accent` 밑줄, 펼쳐진 줄은 화살표가 아래를 본다. 선택 표시에 상태 색을 쓰지 않는다.

**높이(elevation)**: 평면이 기본이다. 면의 층은 선(`--color-border`)과 면의 밝기로 나눈다. 그림자는 `--shadow-overlay` 하나이고 뜬 면(좁은 폭의 서랍, 토스트, 팝오버)에만 쓴다. 카드에는 그림자가 없다.

**다크 테마**: 뒤집지 않고 의미 토큰을 다시 잇는다. 깊을수록 어둡고 뜰수록 밝다(`--color-surface-sunken` → `--color-surface-page` → `--color-surface` → `--color-surface-overlay`). 순검정·순흰색 바탕과 글자를 쓰지 않는다. 상태 글자는 밝고 채도를 낮춘 단계로 바꾸고, 대비는 다크에서 따로 계산한다. 다크 블록 두 개(`@media`, `[data-theme="dark"]`)는 내용이 같아야 한다.

## 타이포그래피

역할 여섯 가지. 크기는 `rem` 고정 단계이고 화면 폭에 따라 바뀌지 않는다. 굵기는 세 단계(`--font-weight-body`, `--font-weight-label`, `--font-weight-strong`)만 쓴다.

| 역할 | 크기 | 줄 높이 | 굵기 | 쓰는 곳 |
|---|---|---|---|---|
| heading | `--font-size-heading` | `--font-line-heading` | `--font-weight-heading` | 페이지 제목(화면에 하나) |
| title | `--font-size-title` | `--font-line-title` | `--font-weight-title` | 카드·서랍·구획 제목 |
| body | `--font-size-body` | `--font-line-body` | `--font-weight-body` | 본문, 설명 |
| label | `--font-size-label` | `--font-line-label` | `--font-weight-label` | 버튼, 탭, 열 제목, 설정 이름 |
| caption | `--font-size-caption` | `--font-line-caption` | `--font-weight-caption` | 보조 정보(저장소, 시각), 배지·칩 |
| code | `--font-size-code` | `--font-line-code` | `--font-weight-code` | 로그 원문, 브랜치·경로 (`--font-family-mono`) |

- 글꼴은 Pretendard(SIL OFL 1.1)이고 그 뒤에 시스템 글꼴이 대체로 선다(`--font-family-sans`). 이 PC에 설치돼 있으면 설치본을 쓰고, 없으면 버전을 고정한 가변 글꼴 파일 하나를 받아 쓴다(`tokens.css`의 `@font-face`).
  - 이것이 "밖에서 아무것도 불러오지 않는다"의 하나뿐인 예외다. 이유: 한글 화면의 인상과 가독성이 글꼴에 크게 달려 있고, 파일을 화면마다 넣으면 단일 HTML이 2MB씩 커진다(리포트는 실행마다 새로 만든다).
  - 범위: 글꼴 파일 하나, 버전 고정 주소. 스크립트·스타일시트·이미지는 여전히 밖에서 불러오지 않는다. 요청에 화면의 데이터는 실리지 않는다(글꼴 제공처는 요청한 IP와 브라우저 정보만 본다).
  - 실패해도 동작한다: 오프라인이거나 막혀 있으면 시스템 글꼴로 보이고(`font-display: swap`) 배치와 기능은 같다.
  - 글꼴 버전을 올릴 때는 주소가 실제로 있는지 확인하고 `tests/run.sh`의 허용 주소를 같이 바꾼다.
- 한국어: `word-break: keep-all` + `overflow-wrap: anywhere`(`.ds-root`가 건다). 본문 줄 높이는 `--font-line-body`. 기울임으로 강조하지 않고 굵기(`--font-weight-strong`)로 한다. 대문자 변환·자간 조정을 쓰지 않는다.
- 숫자를 세로로 견주는 곳(개수, 시각, 표)은 고정폭 숫자(`.ds-num`)를 쓴다.
- 제목은 한 줄에 다 못 들어가면 줄 목록에서는 말줄임, 카드에서는 줄바꿈한다. 카드 본문은 두 줄까지 보이고 나머지는 상세에서 본다.

## 컴포넌트

공용 부품은 `docs/design-system/components.css`에 있고 이름은 `ds-`로 시작한다. 보드에서 세 번 이상 반복되던 패턴만 부품으로 삼았다. 기준 화면이 모든 부품과 상태를 보여 준다.

**쓰임 → 부품** (한 쓰임에 부품 하나)

| 쓰임 | 부품 |
|---|---|
| 그 영역의 주 동작 | `.ds-btn.ds-btn--primary` (영역에 하나) |
| 그 밖의 동작 | `.ds-btn` / 덜 중요한 것은 `.ds-btn--ghost` |
| 되돌릴 수 없는 동작 | `.ds-btn--danger` |
| 다른 곳으로 가기 | 글자 링크(밑줄). PR 열기처럼 동작에 가까우면 `a.ds-btn` |
| 항목의 상태 | `.ds-badge[data-status]` — 항목에 하나, 아이콘 + 글자 |
| 분류·출처 | `.ds-chip` (중립색) |
| 켜고 끄는 필터·대상 | `button.ds-chip[aria-pressed]` |
| 개수 | `.ds-count` — 사람이 할 일의 수만 `data-status="attention"` |
| 같은 목록을 거르기 | `.ds-tabs` / `.ds-tab` |
| 여러 값 중 하나 고르기 | `.ds-segment` (radiogroup) |
| 열 수 있는 항목 | `.ds-card.ds-card--interactive` |
| 읽기만 하는 항목 | `.ds-card` |
| 펼쳐 보는 줄 | `.ds-row` + `button.ds-row__head[aria-expanded]` |
| 같은 원인으로 반복되는 항목 | `.ds-group` — 한 줄 + 개수 + 풀 방법 하나 |
| 설정 값 하나 | `.ds-setting` |
| 화면 단위 경고·안내 | `.ds-notice[data-status]` — 같은 내용은 화면에 한 번, 지금 값이 그 조건일 때만 보인다 |
| 입력 칸 오류 | `.ds-field__error` (칸 바로 아래, 아이콘 + 글자) |
| 항목 상세 | `.ds-drawer` |
| 방금 한 동작의 결과 | `.ds-toast` |
| 비어 있음 / 불러오는 중 / 불러오기 실패 | `.ds-empty` / `.ds-skeleton` / `.ds-error` |

**크기 사다리** — 이 두 크기뿐이다.

| 크기 | 높이 | 좌우 여백 | 글자 역할 | 아이콘 | 쓰는 곳 |
|---|---|---|---|---|---|
| sm | `--size-control-sm` | `--space-2` | caption | `--size-icon-sm` | 카드·줄 안의 동작, 필터 칩 |
| md | `--size-control-md` | `--space-3` | label | `--size-icon` | 페이지 머리, 서랍 바닥, 입력, 탭, 선택 사다리 |

줄 머리의 높이는 `--size-row`, 배지·칩·개수의 높이는 `--size-badge`, 상태 점은 `--size-dot`이다. 반경은 칩·작은 요소 `--radius-sm`, 버튼·입력 `--radius-md`, 카드·서랍·토스트 `--radius-lg`, 배지·개수만 `--radius-full`(버튼에는 쓰지 않는다).

**상태** — 색만으로 구분되지 않게 그린다.

| 상태 | 그리는 법 |
|---|---|
| hover | 바탕이 `--color-surface-hover`. 눌리는 요소에만 있다 |
| focus-visible | `--color-focus` 2px 윤곽 + 바깥 여백. 모든 조작 요소가 같은 모양 |
| active | 바탕이 `--color-surface-selected` (버튼·칩·줄 머리·눌리는 카드·선택 사다리) |
| disabled | 흐리게 + 금지 커서, hover 없음. 왜 못 누르는지 옆에 글로 적는다 |
| loading (버튼) | `aria-busy="true"` — 도는 표시 + 진행형 글자("저장하는 중"). 흐리게 하지 않는다(글자가 읽혀야 한다) |
| selected / open | 위 "선택·열림 표시" |
| invalid (입력) | `--color-danger-border` 윤곽 + `.ds-field__error` |

**부품별 규칙**

- **카드**: 눌리는 카드는 제목이 `button.ds-card__open`이고 그 덮개가 카드 전체를 덮는다 — 마우스는 카드 어디든, 키보드는 제목에서 Enter·Space. 카드 안의 다른 버튼·링크는 `.ds-card__actions`에 둔다(덮개 위로 올라온다). 눌리지 않는 카드에는 hover·커서·조작 윤곽이 없다. 상태는 `.ds-card__meta`의 배지 하나로만 보이고 색 띠를 두르지 않는다. 주 동작은 카드에 하나.
- **목록 줄**: 펼칠 내용이 있으면 머리 전체가 `button[aria-expanded][aria-controls]`이고 화살표가 붙는다. 펼칠 내용이 없으면 `div`이고 화살표·hover가 없다(제목은 같은 선에서 시작한다). `--breakpoint-narrow` 이하에서는 제목을 자르지 않고 줄바꿈하며 곁 정보가 제목 아래로 내려간다. 줄을 펼치면 원문·근거·관련 세션·PR이 그 자리에 나온다. 화면 안의 펼치기는 전부 이 방식 하나다(`<details>`와 섞지 않는다).
- **묶음**: 같은 원인의 항목이 셋 이상이면 묶는다. 한 줄에 원인(사람 말) + 개수, 그 아래 풀 방법 하나(버튼 하나). 구성원은 펼쳐야 보인다.
- **탭**: `role="tablist"`. 좌우 화살표·Home·End로 옮기고 고른 탭만 Tab 순서에 든다. 폭이 모자라면 줄바꿈하지 않고 가로로 민다. 개수는 그 탭에서 사람이 할 일의 수이고, 사이드바·열 제목의 개수와 같은 것을 세어 같은 수가 나와야 한다.
- **서랍**: 열면 포커스가 서랍 제목으로 가고, 닫으면 연 카드로 돌아온다. Esc와 닫기 버튼으로 닫는다. 배경을 가리는 폭에서는 `aria-modal="true"`가 되고, 뒤 화면은 스크롤되지 않고, Tab이 서랍(과 떠 있는 토스트) 안에서 돈다. 연 카드는 선택 표시(`aria-current`)를 하고 닫거나 다른 카드를 열면 지운다. 서랍 내용은 연 항목의 것이다. 주 동작은 서랍 바닥 오른쪽 끝.
- **토스트**: 성공은 `role="status"`로 잠깐 떴다 사라지고(마우스를 올리거나 포커스가 있는 동안은 남는다), 실패는 `role="alert"`로 닫을 때까지 남는다. 실패 토스트는 원인을 말한다. 서랍이 열려 있으면 서랍 바닥의 동작을 덮지 않게 그 위로 올라간다. 닫기 버튼으로 닫으면 포커스는 토스트를 띄운 곳으로 돌아간다.
- **설정 행**: 이름 + 한 줄 설명 | 값. 값이 기본값이면 아무 표시가 없고, 기본값과 다를 때만 "기본값과 다름" 배지(정보)가 붙는다. 기본값인 선택지를 강조색으로 칠하지 않는다. 설명에 환경변수·설정 키 이름을 쓰지 않는다.
- **빈 상태**: 왜 비었는지 한 문장 + 다음에 할 일(있으면 버튼 하나). "데이터 없음"만 쓰지 않는다. 처음 쓰는 화면, 걸러서 0건, 할 일이 없어 0건을 구분해 말한다.
- **로딩**: 내용이 들어올 자리에 실제 내용과 같은 뼈대(`.ds-skeleton`)를 둔다. "불러오는 중" 안내(`role="status"`)는 `aria-busy` 영역 밖에 둔다. `--motion-delay-loading` 뒤에 나타나 빠른 응답에서는 깜빡이지 않는다. 빈 화면으로 기다리게 하지 않는다.
- **오류**: 무엇을 못 했는지(제목) → 원인 → 할 수 있는 일(버튼 하나). 이전 내용이 있으면 지우지 않고 그 위에 알림 줄로 알린다.

**아이콘**: 화면 파일 안의 인라인 SVG 스프라이트(`<symbol>` + `<use>`) 하나가 출처다. 16 단위 격자, 선 굵기 1.5, `currentColor`. 크기는 `--size-icon`과 `--size-icon-sm` 둘. 글자 옆 아이콘은 `aria-hidden="true"`, 아이콘만 있는 버튼은 `aria-label`을 단다. 이모지를 아이콘으로 쓰지 않는다.

**누름 영역**: 조작 요소는 가로세로 `--size-target-min` 이상.

## 문구

보드·리포트의 실제 문자열과 리뷰 지적에서 뽑았다. 말투는 합쇼체("-습니다")이고 CHANGELOG·기존 화면과 같다.

- **제목은 사람 말로.** 카드·줄 제목은 무슨 일인지 한 문장으로 쓴다("결제 승인 응답이 30초 넘게 없음"). 로그 원문·타임스탬프·추적 ID·시그니처 해시·내부 상태 코드를 제목에 쓰지 않는다 — 원문은 펼친 곳에 code 역할로 둔다.
- **오류**: 원인 → 할 수 있는 일. 탓하지 않고, 코드만 던지지 않는다("설정을 저장하지 못했습니다. 설정 파일에 쓸 권한이 없습니다. 권한을 확인한 뒤 다시 저장하세요.").
- **버튼**: 동작을 말하는 짧은 동사형("PR 검토하기", "로그 열기", "다시 불러오기"). 같은 동작은 화면마다 같은 낱말. 진행 중이면 "-하는 중".
- **탭·열 제목·설정 이름**: 명사형("자동 수정", "지금 할 일", "하루 실행 상한").
- **숫자**: 숫자가 소식이면 숫자를 앞에("9건이 함께 풀립니다"). 단위를 붙이고(건·개·분·USD), 시각은 가까우면 상대("12분 전"), 멀면 `YYYY-MM-DD HH:MM`. 같은 것을 세는 수는 화면 어디서나 같다.
- **빈 상태**: 왜 비었는지 + 다음에 할 일. **로딩**: 화면에는 뼈대만, 보조 기술에는 "불러오는 중".
- **설명문**: 한 줄. 기본값은 "기본값 5."처럼 끝에 적는다. 그 탭·그 행의 내용만 말한다.
- **쓰지 않는 말**: 내부 상태 코드와 영어 식별자를 그대로 드러낸 표기 → 사람 말로 푼 상태 이름("PR 상태를 확인할 수 없어 멈춤"), 기능은 한국어 이름("자동 개선", "동기화"). 환경변수·설정 키 이름 → 설정 이름. "오류가 발생했습니다"만 쓰기 → 원인과 할 일. "새 에러"처럼 실제 단계와 다른 배지 말 → 실제 단계 이름(후보·수정 중·PR 검토·해결).
- **정직**: 시스템이 모르는 수·상태를 보여 주지 않는다. 모르면 "확인 못 함"이라고 쓰고 정보 배지를 단다. 예시·자리 표시는 예시처럼 보이게 한다(기준 화면의 데이터는 전부 가짜이고 그렇게 적혀 있다).

## 모션

모션 토큰 이름의 단일 출처다.

| 토큰 | 역할 |
|---|---|
| `--motion-duration-short` | hover·누름·켜고 끄기의 색 변화 |
| `--motion-duration-medium` | 펼치기 화살표, 토스트, 배경 가림 |
| `--motion-duration-long` | 서랍 |
| `--motion-duration-loop` | 로딩 표시의 반복 한 바퀴 |
| `--motion-delay-loading` | 로딩 뼈대가 나타나기 전 기다림 |
| `--motion-ease-standard` | 제자리에서 바뀌는 것 |
| `--motion-ease-enter` | 들어오는 것 |
| `--motion-ease-exit` | 나가는 것 |

- 전환마다 시간 토큰 하나와 곡선 토큰 하나를 쓴다. 부품에 밀리초·곡선 값을 직접 적지 않는다.
- 움직이는 속성은 `opacity`·`transform`과 색이다. 폭·높이 같은 배치 속성은 움직이지 않는다 — 펼치기는 내용을 바로 보이고 화살표만 돈다.
- 끝 상태에서 바로 쓸 수 있어야 한다. 애니메이션이 끝나기를 기다려야 하는 조작이 없다.
- `prefers-reduced-motion: reduce`에서는 이동·회전·반복을 없애고 같은 끝 상태에 바로 닿는다. 테마 전환은 움직이지 않는다.

## 접근성

- **대비**: 글자 4.5:1, 조작 요소 윤곽·상태 표시·포커스 3:1 (WCAG 2.2 AA). 허용한 전경/배경 쌍은 `docs/design-system/contrast-pairs.tsv`에 있고 `scripts/design-system.sh contrast`가 라이트·다크를 따로 계산한다. 새 조합을 쓰려면 그 파일에 줄을 더해 통과시킨다.
- **포커스**: `--color-focus` 윤곽 하나. 없애지 않는다. 포커스 순서는 화면 순서와 같다.
- **키보드**: 조작 요소는 `button`·`a`·`input`으로 만든다. `div`에 click만 달지 않는다. 탭·선택 사다리는 화살표 키, 서랍은 Esc.
- **이름**: 아이콘만 있는 버튼은 `aria-label`. 펼치기는 `aria-expanded`, 켜고 끄기는 `aria-pressed`, 고른 탭은 `aria-selected`, 고른 값은 `aria-checked`, 불러오는 영역은 `aria-busy`.
- **색만으로 알리지 않기**: 상태는 아이콘 + 글자, 선택은 윤곽·밑줄 + 굵기, 오류는 아이콘 + 글.
- **알림**: 토스트는 저마다 `role="status"`(성공)·`role="alert"`(실패)를 갖는다. 토스트 영역에 `aria-live`를 겹쳐 달지 않는다(두 번 읽힌다).
- **누름 영역**: `--size-target-min` 이상.
- **강제 색 모드**: 바탕색만으로 구분하던 경계는 선으로 보인다(`components.css`의 `forced-colors` 블록).

## 반응형

| 폭 | 바뀌는 것 |
|---|---|
| `--breakpoint-wide` 이상 | 서랍이 목록 옆에 서고 목록의 열이 한 줄로 접힌다 |
| `--breakpoint-wide` 미만 | 서랍이 배경을 가리고 목록 위에 뜬다(Tab이 서랍 안에서 돈다) |
| `--breakpoint-narrow` 이하 | 사이드바가 본문 위로 올라가고, 본문 여백이 `--space-4`로 줄고, 설정 행의 값이 이름 아래로, 목록 줄의 곁 정보가 제목 아래로 내려간다 |

- 열은 정한 개수가 아니라 열 최소 폭(`--size-column-min`)으로 접힌다.
- 지원 최소 폭은 `--size-viewport-min`. 그 폭에서 가로 스크롤이 생기지 않는다(코드 원문 블록 안은 예외).
- 글자 크기와 조작 요소 높이는 폭에 따라 바뀌지 않는다.

## 토큰 변경 규칙

- **더하기**: 같은 뜻으로 세 번 이상 쓰는 값만 토큰이 된다. 이름은 `--color-<역할>-<변형>-<상태>`, `--space-<단계>`, `--size-<쓰임>`, `--font-<속성>-<역할>`, `--radius-<단계>`, `--shadow-<쓰임>`, `--motion-<속성>-<역할>`, `--z-<층>`. 색 토큰은 라이트·다크 값을 함께 넣고 쓰는 조합을 `contrast-pairs.tsv`에 더한다.
- **순서**: `tokens.css`(원본) → `scripts/design-system.sh sync` → `scripts/design-system.sh contrast` → 이 문서의 표 → 기준 화면의 예시. 부품을 바꾸면 기준 화면의 그 예시도 같은 변경에서 바꾼다.
- **이름 바꾸기·없애기**: 쓰는 곳을 전부 옮긴 뒤 없앤다. 보드·리포트의 예전 변수 이름(각 화면 `<style>` 머리의 연결 블록)은 그 화면을 재구성할 때 없앤다.
- **화면에서 값 직접 쓰기**: 새 화면·새 부품은 색·간격·크기 값을 직접 적지 않는다. 토큰에 없는 값이 필요하면 토큰을 먼저 더한다.
- **확인**: 값·규칙의 변경은 저장소 관리자가 PR에서 확인한다. 확인된 결정은 `## 결정 기록`에 옮긴다.

## 결정 기록

- 2026-11-10 — **글꼴은 Pretendard.** 설치본 우선, 없으면 버전 고정 파일 하나를 받는다. 대안: 시스템 글꼴만(밖으로 요청 없음, 플랫폼마다 인상이 다름), 글꼴 파일을 화면에 넣기(요청 없음, 화면마다 2MB). 화면이 밖으로 보내는 요청은 이것 하나로 묶는다.
- 2026-11-10 — **밀도는 여유 있는 것 하나, 반경은 한 단계 크게, 본문 글자는 한 단계 크게.** 작업 도구이지만 "부드럽고 읽기 편하게"가 우선이다. 대안: 처음 제안한 조밀한 밀도(한 화면에 더 많이 보이지만 빽빽함), 밀도 모드 둘(화면이 둘뿐이라 과함).

## 레퍼런스에서 가져온 것

`awesome-design` 스킬에 든 공개 디자인 명세 여섯 개(linear.app, sentry, vercel, posthog, raycast, supabase의 `DESIGN.md`)를 읽고 **원칙만** 가져왔다. 색 값·글꼴·로고·이름은 가져오지 않았다. 여섯 명세는 모두 마케팅 사이트를 적은 것이라 제품 화면의 서랍·빈 상태·로딩은 다루지 않는다 — 그 부분은 명세가 아니라 독립 디자인 리뷰와 WCAG에서 유도했고 표에 그렇게 적었다.

| 주제 | 가져온 원칙 | 출처 | 이 문서의 어디 |
|---|---|---|---|
| 밀도 | 구분은 간격+그림자가 아니라 선으로, 간격은 눈대중이 아니라 단계로 재서 쓴다 | posthog §5 "Content-dense by design", 카드 안쪽·요소 사이 간격 / supabase §5 "Dense content blocks", "Border-defined space" / raycast §5 "Dense product, sparse marketing" | 밀도 하나(여유 있는 쪽), 4px 기준 간격, 카드 그림자 없음 |
| 상태 색 | 색은 기능이고 장식이 아니다. 상태·단계 색은 그 맥락에만 쓴다. 강한 색은 구두점처럼 드물게 | vercel §7 "Apply workflow accent colors only in their workflow context", §9 "Color is functional, never decorative" / linear.app §1·§7 "Success green used only for status indicators", 강조색은 조작 요소에만 / supabase §7 따뜻한 색은 상태용 의미 토큰으로만 / raycast §7 빨강은 "punctuation, not pervasive" | 원칙 1, 상태 표, 빨강은 실패에만 |
| 상태의 면 | 상태 글자색과 같은 색조의 옅은 면을 짝으로 둔다 | raycast §2 Semantic 색과 같은 색조의 투명 면(위험·정보) / vercel §2 배지의 옅은 바탕 + 진한 글자 짝 | 상태마다 글자 / 옅은 면 / 경계 / 채운 면 |

| 포커스 | 포커스 표시는 한 가지 모양으로 모든 조작 요소에, 그 색은 다른 뜻에 쓰지 않는다 | vercel §4·§6 모든 조작 요소에 같은 2px 포커스 윤곽 / posthog §2 포커스 색은 "accessibility-only" | `--color-focus` 하나 (여기서는 파랑이 "진행"이라 무채색으로 정했다) |
| 배지 | 상태는 알약 모양 + 옅은 바탕. 분류 태그는 중립 테두리. 알약 반경은 배지에만 쓰고 버튼에는 쓰지 않는다 | vercel §1·§7 "pills are for badges/tags only" / linear.app §4 Neutral Pill(분류·필터)과 상태 표시의 구분 / raycast §4 Neutral badge | 배지(상태)와 칩(분류) 분리, 반경 규칙 |

| 숫자 | 견주는 숫자는 고정폭 | vercel §3 `"tnum"` | `.ds-num` |

**가져오지 않은 것과 이유**

- 속삭이듯 옅은 반투명 경계를 조작 요소에(linear.app §7, raycast §7, vercel §7의 0.05–0.1 불투명도 선) — 조작 요소 윤곽 3:1을 못 채운다. 리뷰가 잡은 경계 대비 미달이 바로 이 모양이다. 구획선(`--color-border`)에만 옅은 선을 쓴다.
- hover를 불투명도로 낮추기(raycast §4, posthog §4) — 글자 대비가 떨어진다. hover는 바탕 면을 바꾼다.
- 대문자 라벨과 자간(sentry §3, supabase §3) — 한글에는 대소문자가 없다.
- 음수 자간·OpenType 설정과 그 명세들의 전용 글꼴(linear.app, vercel) — 글꼴은 한글 화면에 맞는 Pretendard를 골랐고(명세에서 온 것이 아니다) 자간은 건드리지 않는다.
- 촘촘한 덩어리와 작은 반경(posthog §5 카드 안쪽 여백, §7 "Don't apply large border-radius (12px+) on cards") — 사용자 확인(2026-11-10, PR #288)에서 "부드럽고 읽기 편하게"가 우선이라 여백·줄 높이·반경을 한 단계씩 키웠다. 작업 도구라 밀도 모드는 여전히 하나다.
- 눌린 듯한 안쪽 그림자, 유리 효과, 빛 번짐(sentry, raycast) — 장식이고 상태를 말하지 않는다.
- 어두운 바탕에서 본문 굵기를 한 단계 올리기(raycast §3) — 글꼴을 못 받아 시스템 글꼴로 보일 때 중간 굵기가 플랫폼마다 달라 본문은 한 굵기로 둔다.
- 브랜드 색 전부(각 명세 §2) — 이 시스템의 색은 상태의 뜻에서 정했다.
